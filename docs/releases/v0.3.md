## 1. 目标与成功标准

补齐「收集」的最后两块：截图和网页。用户可以保存图片并通过图片里的文字搜到它；保存网址后能直接看到网页标题与摘要；回收站可以永久删除，到期内容会被自动清理。

- 「截图用于参考交互」验收场景（PRODUCT）端到端通过。
- 图片识别文字与网页正文参与关键词搜索。
- 永久删除与到期清理会删除数据库记录、对象存储文件与派生数据，并在备份恢复后可以重放。

## 2. 范围

| 包含 | 不包含 |
| --- | --- |
| 每条最多 9 张图片（JPEG、PNG、GIF、WebP，单张 5 MiB）：选择、粘贴、拖拽、进度、重试、移除 | 图片编辑、标注、视频 |
| 私有 OSS 存储、直传预签名、短时下载授权 | 公开图片链接、CDN 加速 |

| 回收站永久删除、30 天到期清理、删除账本 | 账号注销 |

## 3. 方案设计

### 3.1 上传与附件（F-02）

生产接入采用服务端调用区域 STS。上海 STS 的区域 ID 为 `cn-shanghai`，与 OSS 的 endpoint 配置分别传入 SDK。操作员通过受限输入保存长期凭证，仓库、PR、构建和客户端均只使用合成配置。v0.2 的导出直接从 PostgreSQL 生成 ZIP，导出无需 OSS 授权。

首次启用附件前，应在 RAM 控制台核对调用身份仅可 AssumeRole 到指定角色、角色信任关系及桶的私有 ACL。共用桶须为 Spark 分配独立对象前缀；下文对象键均相对于该前缀。服务端按已认证账号、操作和具体对象限制会话策略，以 900 秒 STS 凭证签发有效期更短的 PUT/GET，只向客户端返回具体对象的短时 URL。私有密钥文件只读挂载给实际签名的服务；角色变更、轮换和旧密钥撤销由操作员执行。先用专属测试前缀和合成图片验证归属、过期及删除，避免操作其他业务对象。[阿里云 STS 授权说明](https://www.alibabacloud.com/help/zh/oss/sts-temporary-access-authorization)

流程沿用契约中已定义的上传接口：

1. 前端为每张图片调用 `POST /uploads`（文件名、声明类型、大小），后端校验数量与大小，返回上传 ID 与 OSS 预签名 PUT 地址（有效 10 分钟）。
2. 浏览器直传 OSS，用 `XMLHttpRequest` 上报进度；失败可重试或移除。
3. 调用 `POST /uploads/{id}/complete`：后端用范围读取对象头部校验真实类型（魔数）、核对大小与归属，记录 `sha256`，状态置为 `ready`。
4. 创建或编辑收藏时携带 `upload_ids`，在同一事务中把就绪的上传转为 `attachments`，按顺序写入 `position`。

- 预签名与对象键：`users/{user_id}/uploads/{upload_id}`，桶策略禁止公开读；OSS 跨域配置只允许站点来源的 `PUT`。
- 下载：卡片与详情通过下载授权接口获取短时签名地址（有效 5 分钟），过期由前端按需刷新（WEB.md 已有约定）。
- 清理：超过 24 小时未使用的上传由维护任务删除对象与记录。
- 前端：收集框新增图片工具（替换当前的占位约束），预览缩略图带进度环；卡片单图显示为大图、多图为九宫格；详情页支持放大浏览。

### 3.2 图片文字识别（F-02）

- 新增 River 任务 `extract_image`：收藏保存或附件变化后入队，按附件调用 OCR 服务，结果写入 `extractions`（`source_kind = image`）。
- 服务适配层只暴露「输入对象地址，返回文字与置信度」，选型确定后实现具体适配器；未配置时状态为 `skipped`，不影响保存。
- 失败重试 3 次（指数退避），不可恢复错误（格式不支持、内容过大）直接标记失败。
- 识别文字参与搜索，命中片段标注「图片文字」。

### 3.3 网页正文与链接预览（F-03）

- 新增 River 任务 `extract_url`：对收藏的主要网址抓取网页，提取标题、站点名与正文摘要，写入 `extractions`（`source_kind = url`）。
- 抓取安全：仅 HTTP(S)；解析并固定 IP，拒绝内网、回环、链路本地与保留地址；每次重定向重新校验，最多 3 跳；超时 8 秒；响应上限 2 MiB；只解析 HTML。可复用桌面版 `internal/urltitle` 的校验思路，在 `server/` 内独立实现并测试。
- 正文提取先使用规则方式（标题、`og:` 元数据、主要段落），是否引入可读性解析依赖在实现前评估维护状态与许可证。
- 前端：卡片正文下方显示链接小卡（站点名、标题、两行摘要）；抓取中显示「正在获取网页信息」；失败时只保留网址；详情页提供「重新获取」。

### 3.4 永久删除与到期清理

- `POST /collections/{id}/purge`：仅回收站内的收藏可永久删除，二次确认后执行。
- 每日 River 定时任务清理 `purge_after` 已过期的收藏。
- 删除顺序：事务内写入 `deletion_ledger`（对象键列表）并删除数据库记录、保留最小墓碑 → 事务外删除 OSS 对象 → 完成后标记账本。失败由任务重试，不影响用户可见结果。
- 前端：回收站显示剩余天数与「永久删除」，删除中显示「清理中」。

## 5. 测试与验收

- **安全**：伪造扩展名与魔数被拒绝；他人上传 ID、附件 ID 与下载授权不可用；内网地址与非 HTTP(S) 被拒绝；重定向到内网被拒绝。
- **一致性**：上传完成前收藏不可引用；编辑时移除的附件在修订历史中保留引用规则正确；永久删除后搜索、列表、下载均不可见，对象存储文件被删除。
- **恢复**：模拟 OSS 删除失败，任务重试后完成；从备份恢复后重放删除账本。
- 各需求的验收标准见 ITERATION F-02、F-03 与 ROADMAP M2、M3。

## 6. 发布与回滚

- 发布顺序：执行迁移 004 → 部署 API 与 Worker（OCR、抓取开关默认关闭）→ 发布 Web → 逐项打开开关。
- 回滚：关闭 OCR 与抓取开关即可停止新任务；Web 回退到 v0.2 时隐藏图片入口，已保存的附件保留，不删除数据。
