## 1. 目标与成功标准

补齐「收集」的最后两块：截图和网页。用户可以保存图片并通过图片里的文字搜到它；保存网址后能直接看到网页标题与摘要；回收站可以永久删除，到期内容会被自动清理。

- 「截图用于参考交互」验收场景（PRODUCT）端到端通过。
- 图片识别文字与网页正文参与关键词搜索。
- 永久删除与到期清理会删除数据库记录、对象存储文件与派生数据，并在备份恢复后可以重放。

## 2. 范围

| 包含 | 不包含 |

| 每条最多 9 张图片（JPEG、PNG、GIF、WebP，单张 5 MiB）：选择、粘贴、拖拽、进度、重试、移除 | 图片编辑、标注、视频 |
| 私有 OSS 存储、直传预签名、短时下载授权 | 公开图片链接、CDN 加速 |

## 3. 方案设计

### 3.1 上传与附件（F-02）

平台使用既有 RAM 用户的 AK/SK，由 API 和处理附件的 Worker 通过只读文件加载。共享桶的测试与生产使用独立前缀。服务端验证用户、附件归属和状态后，用 OSS V4 为具体方法和对象签名；PUT 绑定暂存键、类型和长度，有效期最多 600 秒，GET 绑定最终对象，有效期最多 300 秒。签名查询串含 AccessKey ID，Secret 只在服务端使用。签名 URL 在到期前可使用，应用日志不得记录完整链接。

`oss-v2` 配置显式指定 OSS 区域、端点、桶和环境前缀。切换时同步更新私有配置并重建持有凭据的服务。权限范围由 RAM 用户和桶策略决定；长期密钥泄露的影响取决于云端授权。轮换或撤销由资产负责人执行。配置及文件权限见[后端说明](../../server/README.md)。

流程沿用契约中已定义的上传接口：

1. 前端为每张图片调用 `POST /uploads`（文件名、声明类型、大小），后端校验数量与大小，返回上传 ID 与 OSS 预签名 PUT 地址（有效 10 分钟）。
2. 浏览器直传 OSS，用 `XMLHttpRequest` 上报进度；失败可重试或移除。
3. 调用 `POST /uploads/{id}/complete`：返回 `202`。服务端将临时对象复制到仅服务端可写的最终键，对最终对象校验归属、实际大小和图片格式，计算完整文件的 `sha256`；通过后置为 `ready`。客户端通过 `GET /uploads/{id}` 查询校验结果。详见[附件时序](../design/API.md#附件时序)。
4. 创建或编辑收藏时携带 `upload_ids`，在同一事务中把就绪的上传转为 `attachments`，按顺序写入 `position`。

- 临时 PUT 授权使用暂存键 `users/{user_id}/uploads/{upload_id}`。桶策略禁止公开读，OSS 跨域配置只允许站点来源的 `PUT`。
- 下载：卡片与详情通过下载授权接口获取短时签名地址（有效 5 分钟），过期由前端按需刷新（WEB.md 已有约定）。
- 存储端由独立资产 Worker 确认图片和执行到期清理。超过 24 小时的暂存对象及未绑定的最终对象进入清理，未绑定记录在对象删除成功后移除。
- 前端：收集框新增图片工具（替换当前的占位约束），预览缩略图带进度环；卡片单图显示为大图、多图为九宫格；详情页支持放大浏览。

### 3.2 图片理解（F-02）

- 首期使用 `deepseek-flash` 的非思考模式。用户明确同意发送图片后，Worker 只读取已确认附件的最终图片，随固定提示以内联图片提交。每次只处理一张，要求一次返回「图中文字」和「AI 画面描述」。识别不清的文字留空，两类结果分别作为纯文本展示并参与关键词搜索。模型输出达到上限时说明结果可能不完整。专用 OCR 仅作为用户主动精确提字的后续选项。[图像理解接口](https://api-docs.deepseek.com/zh-cn/guides/vision/)
- 仅处理新绑定且获准分析的图片；历史收藏不自动回填。任务按账号、附件的稳定内容标识及识别版本去重。刷新、排序或只编辑备注复用已有结果。派发前核对授权、排除与删除状态，缺少图片授权时仍可正常保存。结果仅写回仍有效的附件。
- 首期建议硬限为单图 1,536 个输入 token（图片最多 1,024，剩余 512 供固定提示和消息封装）和 512 个输出 token。发送前确认输入上界，显式限制输出。按 2026-11-19 的高峰未命中价估算，输入每百万 token 2 元、输出 8 元，对应每图预留 7,168 微元。价格与模板变动时重新核定。单图预留是预算估算，真实用量与供应商账单分别核对。[官方价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)
- 图片与文字整理共用 PostgreSQL 的平台、用户日额度。并发事务先预留，再派发；余额不足保留图片并暂停分析。已发送请求缺少可靠计量时保留待核对金额，不自动重发或切换供应商。开发使用受控端点验证重复入队、并发抢额度、额度为零和断线的调用次数。真实试用前用少量合成截图与照片检验文字找回、画面找回、截断率和每张费用。

### 3.3 网页正文与链接预览（F-03）

- 新增 River 任务 `extract_url`：对收藏的主要网址抓取网页，提取标题、站点名与正文摘要，写入 `extractions`（`source_kind = url`）。
- URL Worker 独立启动，抓取开关默认关闭。读取及重新获取见 [网页信息提取 API](../design/API.md#网页信息提取)。
- 抓取安全：仅 HTTP(S)；解析并固定 IP，拒绝内网、回环、链路本地与保留地址；每次重定向重新校验，最多 3 跳；超时 8 秒；响应上限 2 MiB；只解析 HTML。可复用桌面版 `internal/urltitle` 的校验思路，在 `server/` 内独立实现并测试。
- 正文提取先使用规则方式（标题、`og:` 元数据、主要段落），是否引入可读性解析依赖在实现前评估维护状态与许可证。
- 前端：卡片正文下方显示链接小卡（站点名、标题、两行摘要）；抓取中显示「正在获取网页信息」；失败时只保留网址；详情页提供「重新获取」。

### 3.4 永久删除与到期清理

- `POST /collections/{id}/purge`：仅回收站内的收藏可永久删除，二次确认后执行。
- 每日 River 定时任务清理 `purge_after` 已过期的收藏。
- 永久删除请求的事务登记删除并立即隐藏收藏。清理任务删除数据库内容和 OSS 对象，复制独立删除清单后标记账本完成。重试和墓碑见 [删除与恢复](../design/DATA.md#删除与恢复)。
- `GET /collections/{id}/purge` 返回清理状态。前端回收站显示剩余天数与「永久删除」，登记后显示清理中。

## 5. 测试与验收

- **安全**：伪造扩展名与魔数被拒绝；他人上传 ID、附件 ID 与下载授权不可用；内网地址与非 HTTP(S) 被拒绝；重定向到内网被拒绝。
- **一致性**：上传完成前收藏不可引用；编辑时移除的附件在修订历史中保留引用规则正确；永久删除后搜索、列表、下载均不可见，对象存储文件被删除。
- **恢复**：模拟 OSS 删除失败，任务重试后完成；从备份恢复后重放删除账本。
- 各需求的验收标准见 ITERATION F-02、F-03 与 ROADMAP M2、M3。

## 6. 发布与回滚

- 发布顺序：执行迁移至 007 → 部署 API 与 Worker（图片理解和抓取开关默认关闭）→ 发布 Web → 逐项打开开关。
- 回滚：关闭图片理解与抓取开关可停止新任务登记。停止对应 Worker 可暂停处理剩余队列。Web 可回退到 v0.2 并保留附件。API 与 Worker 启动要求匹配数据库版本，回退旧版本程序需要按备份恢复方案同步回退数据库。
