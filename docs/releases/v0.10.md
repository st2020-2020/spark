# v0.10.0 项目、笔记与附件删除

基线为 v0.9.0，数据库沿用 v20。项目、笔记删除及文件回执的隔离验收版本为 `234dc2c6`。

## 用户操作

- 在项目详情删除本人项目，确认后解除该项目与收藏的关联。一条收藏可属于多个项目，删除其中一个项目后仍能打开收藏、图片和其他项目。
- 笔记先进入回收站。30 天内可连同附件恢复，也可以选择提前永久删除。永久删除一经受理，由清理 Worker 处理；对象存储失败时保留重试记录。界面以清理任务的实际状态展示进度。
- 权限沿用现有账号与设备范围。日常浏览、搜索或打开回收站无需写入删除任务。

## 实施与验收

| 负责范围 | 交付与验收 |
| --- | --- |
| 后端及契约 | 项目删除校验归属、版本与幂等。双账号覆盖越权，同一笔记关联多个项目，验证删除项目后笔记可读。 |
| Web | 项目详情给出删除后果及确认入口。覆盖取消、重复点击、其他端先修改或删除、返回项目列表和刷新。笔记永久删除在回收站确认。 |
| 附件与发布 | 在隔离对象存储实际上传两套图片。软删与恢复核对原图，永久删除一条后核对对象清单、相邻收藏与完成回执，覆盖失败或重启后继续清理。 |
| 发布 | 独立分支经密钥扫描、正式 PR、三项 CI 与人工审查。核验主干、标签及部署版本，停写备份实际恢复验证；线上核对服务健康、清理 Worker 就绪与配置。 |

桌面 Chrome（1440×900）实测取消删除后仍可编辑原草稿，转存收件箱后删除项目返回 204。同一笔记仍可打开原文和图片，且保留另一项目归属。笔记移入回收站后可撤销。窄屏 Chrome（390×844）确认永久删除返回 202，刷新后显示清理完成，换号无法读取该收藏。两种视口均无横向溢出。后端全量测试、构建、vet 及契约生成比对通过，Web 211 项测试、类型检查和构建通过。

在隔离环境将删除前的 v20 备份完整恢复，再重放独立回执。已永久删除的收藏和附件未重新出现，相邻收藏仍在。另验证停写备份可完整恢复，以及回退至旧版本后 API 和附件服务健康，永久清理 Worker 停止。

## 运维要求

生产删除回执选用现有阿里云 OSS 的专用私有前缀，与附件前缀分开。发布前使用合成对象，以部署使用的权限验证同键创建、拒绝覆盖、内容读回和按前缀列举。回执保留期限须覆盖仍可恢复的最早备份。仅在完成权限验证和离线重放验收后启用永久删除，并设置固定 UTC 到期切线，后续重启沿用原值。

旧备份的恢复按[部署说明](../../deploy/README.md)在隔离库完成。须从 OSS 列举并重放全部回执，确认已永久删除的笔记和附件未复活，且相邻收藏仍可读。上述文件回执的验收结果不覆盖 OSS 权限和分页。已有文件回执部署继续沿用原存储。

### 云账号管理员需要确认的范围

以下用 `spark-deletion-ledger/` 举例。选定现有桶中一个私有前缀，核对它与附件、临时上传和自动过期规则的范围均分开。对于已启用或暂停版本控制的桶，OSS 会忽略禁止覆盖的请求头；此时应停止该次启用，保留现有桶策略。[OSS PutObject 约定](https://www.alibabacloud.com/help/en/oss/developer-reference/putobject)

| 使用方 | 对象权限 | 桶级权限 |
| --- | --- | --- |
| 永久清理 Worker | 对 `spark-deletion-ledger/receipts/*` 创建和读回回执 | 读取版本控制状态 |
| 离线恢复 | 只读同一 `receipts/*` | 读取版本控制状态，按精确前缀 `spark-deletion-ledger/receipts/` 列举 |
| 上线验权 | 用上述真实身份另在同级 `probes/*` 创建、读回合成对象，恢复身份只读 | 按精确前缀 `spark-deletion-ledger/probes/` 列举 |

RAM 策略中，对象操作的资源指向前缀内的对象；列举操作的资源指向桶，使用 `oss:Prefix` 限制可列举的范围。核对身份的其他策略与桶策略，确保附件日常读写身份无法覆盖或删除回执，回执写入和恢复身份均无删除回执的权限。在专用前缀配置服务端禁止覆盖时，应保留应用的条件创建，以应对并发写入同一个新键。生产交接只交换前缀、凭据文件所在路径及验证结果。[RAM 目录授权](https://www.alibabacloud.com/help/en/oss/user-guide/access-control-base-on-ram-policy) · [OSS 禁止覆盖规则](https://www.alibabacloud.com/help/en/oss/user-guide/prevent-file-overwrite)

以下是供管理员核对或配置的两份 RAM 策略示例。将 `YOUR_BUCKET` 和示例前缀替换为实际值，分别绑定到对应身份。已有更宽的 Allow 仍可能生效，须结合桶策略和其他授权核验。两份示例包含发布前合成探针所需权限。

**回执写入身份**

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["oss:GetBucketVersioning"],
      "Resource": ["acs:oss:*:*:YOUR_BUCKET"]
    },
    {
      "Effect": "Allow",
      "Action": ["oss:PutObject", "oss:GetObject"],
      "Resource": [
        "acs:oss:*:*:YOUR_BUCKET/spark-deletion-ledger/receipts/*",
        "acs:oss:*:*:YOUR_BUCKET/spark-deletion-ledger/probes/*"
      ]
    },
    {
      "Effect": "Allow",
      "Action": ["oss:ListObjects"],
      "Resource": ["acs:oss:*:*:YOUR_BUCKET"],
      "Condition": {"StringEquals": {"oss:Prefix": ["spark-deletion-ledger/probes/"]}}
    }
  ]
}
```

**恢复只读身份**

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["oss:GetBucketVersioning"],
      "Resource": ["acs:oss:*:*:YOUR_BUCKET"]
    },
    {
      "Effect": "Allow",
      "Action": ["oss:GetObject"],
      "Resource": [
        "acs:oss:*:*:YOUR_BUCKET/spark-deletion-ledger/receipts/*",
        "acs:oss:*:*:YOUR_BUCKET/spark-deletion-ledger/probes/*"
      ]
    },
    {
      "Effect": "Allow",
      "Action": ["oss:ListObjects"],
      "Resource": ["acs:oss:*:*:YOUR_BUCKET"],
      "Condition": {"StringEquals": {"oss:Prefix": [
        "spark-deletion-ledger/receipts/", "spark-deletion-ledger/probes/"
      ]}}
    }
  ]
}
```

将已验证的探针 UUID 及对应桶、地域和前缀随恢复配置另存，在数据库或系统盘不可用时仍能取得。恢复旧备份时先读回该已知探针，避免将错误前缀的空列表当作“从未删除过”。
