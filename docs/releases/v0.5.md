## 1. 目标与成功标准

让存进去的资料重新被看到、被用上，并给用户一个按时间回看的入口。

- 内测用户中，重现卡片的点击或归类比例可以观察到（需 ITERATION D-01 的度量结论）。
- 日历计数与按日筛选结果一致，跨时区与跨月正确。

## 3. 方案设计（概要）

### 3.1 灵光重现

- 新接口 `GET /me/resurface`：服务端按用户本地日期生成当日结果并缓存到当日结束，保证同一天结果稳定。
- 选取顺序：7 天以上仍待归类 → 进行中项目下 30 天以上未打开 → 往年同一天。只返回本人未删除的资料。
- 「打开时间」：倾向新增 `last_opened_at`（打开详情时更新），替代以 `read_at` 近似；以 D-05 结论为准。
- 「今天不再显示」与关闭开关存为轻量偏好记录。

### 3.2 灵光日历

- 实现契约已有的 `created_from` / `created_to` 筛选。
- 新接口 `GET /me/activity?from=&to=&tz=`：返回按本地日期聚合的收藏数，只统计未删除收藏。
- 前端：桌面侧栏底部月历热力图，手机放在「更多」面板顶部；颜色深浅使用主色透明度档位，同时提供数字，不只依赖颜色。点击某天把收件箱筛选到当天，日期印章高亮，标题区可一键清除。

### 3.3 数据变更（待确认）

- `collections.last_opened_at`（可选，取决于 D-05）。
- 用户偏好：重现开关与当日隐藏记录。
