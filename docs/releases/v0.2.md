## 1. 目标与成功标准

把「归类」从负担变成几分钟就能完成的小事，并让用户确信数据可以随时带走；同时在真实后端下确认 v0.1 与新视觉可用，为邀请内测打好基础。

- 待归类可以在手机上一张张快速处理：每条一次点击即可归入项目，并且可以撤销。
- 用户可以一键导出本人未删除的收藏与全部项目，得到可读的 Markdown 或完整的 JSON。
- 手机可以把 Spark 添加到主屏幕，像应用一样打开。
- v0.1 首批业务与「灵光手帐」视觉在 OrbStack 真实后端下通过浏览器复验；Web 测试在默认配置下稳定通过。

## 3. 方案设计

### 3.1 整理模式（F-01）

**入口与路由**

- 新路由 `/unclassified/triage`，页面组件 `TriagePage`。
- 入口：待归类页标题区「开始整理」主按钮；收件箱已加载的收藏中存在待归类资料时，筛选条下方显示「有待归类的收藏，开始整理」。

**数据**

- 队列来源：`listCollections({ scope: 'unclassified', limit: 30 })`，按游标续取；队列只在前端维护。
- 候选项目：卡片自身 `projects` 中 `decision = suggested` 的项目排在最前（显示「建议」标识与依据摘录），其后为进行中项目（`listProjects({ state: 'active' })`），最后为「更多项目」展开。
- 进度显示「本轮已处理 i 条」。现有列表只在指定 `has_suggestion` 时计算总数；普通待归类队列沿用现有游标，按收藏 ID 去重。跳过的条目可稍后继续，连续跳过至本轮末尾时允许结束，避免无限循环。

**操作与状态**

| 操作 | 实现 | 本地状态 |
| --- | --- | --- |
| 选择项目（可多选，确认后提交） | 单点即提交；多选一次发送同一收藏的 operations。提交前核对所选建议仍有效，服务端在同一事务校验页面所见版本并处理全部选择 | 当前卡片出队，记录最近一次操作 |
| 跳过 | 无请求 | 卡片移到队尾 |
| 不属于任何项目 | 无请求 | 记入本轮已处理集合，本轮不再出现 |
| 撤销上一步 | 归类写入成功后使用本次操作回执一次撤销；本地跳过或移出只恢复队列位置 | 卡片回到队首 |

- 并发冲突：沿用 `decision_version` 与安全决定流程；遇到过期建议时提示「这条建议已在其他地方处理」，刷新该卡片后继续。
- 完成态：队列清空时显示瓶子插画、本轮归入数量与「返回收件箱」。

**撤销设计（T01 拟定契约）**

现有 `reset` 会删除人工决定行，`exclude` 会写入拒绝。两者都不能把已确认的建议准确还原。整理提交沿用项目决定 PATCH，带幂等键的整理操作在同一事务记录服务端读到的变更前状态，响应追加可选撤销回执。普通详情页调用继续沿用原契约。拟复用现有 `idempotency_keys` 的独立操作名及到期清理，客户端仅携带操作键和版本。每轮 UI 只提供上一步。

新增受会话与 CSRF 保护的撤销操作。后端按账号、收藏、操作键核对回执及提交后版本；校验涉及项目、建议来源和正文版本仍有效，再原子还原本次改动。新增手动关联还原为无关联，确认建议还原原决定与引文。重放同一请求只生效一次。版本冲突、回执过期或建议已失效时显示刷新提示并保留最新决定，禁止用客户端指定的旧值覆盖。

**交互实现**

- 卡片堆：当前卡片完整显示，下一张露出边缘；卡片飞入所选胶带用 CSS 变换，减少动效偏好下直接切换。
- 手势：基于 Pointer Events，左滑为跳过，右滑展开项目选择；位移超过阈值才触发，所有手势都有等价按钮。
- 键盘：`1`–`9` 选择项目，`Enter` 确认，`S` 跳过，`Z` 撤销，`Esc` 退出；输入法组合期间与焦点在输入框时不响应。
- 视觉沿用纸条卡片与纸胶带，规范补充写入 [WEB-VISUAL.md](../design/WEB-VISUAL.md)。

### 3.2 数据导出（F-06）

**接口**：`GET /api/v1/me/export?format=markdown|json`

- 需要有效会话；只导出当前用户的未删除收藏与全部项目。
- 响应为流式 `application/zip`，文件名 `spark-export-YYYYMMDD.zip`（北京时间日期）。
- 限流：每用户 10 分钟 1 次，超出返回 `429` 与 `Retry-After`。

**压缩包内容**

| 格式 | 结构 |
| --- | --- |
| `markdown` | `projects/<项目名>/<YYYY-MM-DD>-<标题>.md`；有多个项目的收藏放在第一个项目下，并在文件内列出全部项目；`unclassified/` 放待归类；`README.md` 说明结构与导出时间 |
| `json` | `spark-export.json`：版本号、导出时间、项目数组、收藏数组（正文文档、纯文本、用途、来源网址、标题、时间、项目关联及决定状态） |

单个 Markdown 文件包含：标题（自定义标题或正文首行）、元数据（创建与更新时间、来源网址、用途、项目）、正文。文件名去除路径分隔符与控制字符，过长截断，同名时追加序号。

**实现要点**

- 导出从同一只读快照读取项目和收藏，按用户限定每一批；ZIP 条目名同时清洗项目名与标题，响应设置私有禁止缓存。
- 后端按游标分批读取（每批 200 条），边读边写入 `zip.Writer`，不在内存中聚合全量数据。
- 新增 Spark 文档 → Markdown 的转换函数（段落、加粗、高亮写成 `==文本==`、列表、链接），配单元测试。
- 请求上下文取消时停止读取；日志只记录用户 ID、条数、耗时与结果，不记录内容。

**前端**：设置页新增「导出我的数据」卡片，格式用分段控件选择，按钮即下载链接；限流时显示可再次导出的时间。

### 3.3 添加到主屏（F-10）

- 新增 `apps/web/public/manifest.webmanifest`：`name: Spark 灵光`、`short_name: Spark`、`start_url: /inbox`、`display: standalone`、`background_color` 与 `theme_color` 使用薄荷晨雾浅色背景 `#f2f8f6`。
- 图标：`icon-192.png`、`icon-512.png`、`maskable-512.png`、`apple-touch-icon.png`（180），由小瓶子标志导出后提交为静态资源；不新增构建依赖。
- `index.html` 增加 manifest 与 `apple-touch-icon` 链接。不注册 Service Worker。
- 验证：iOS Safari 与 Android Chrome 添加到主屏后，启动背景、安全区与底部悬浮坞位置正确。

### 3.4 联调复验（O-01）与测试超时（O-04）

- 在 OrbStack 容器栈用真实账号完成：登录 → 建项目 → 收集（收件箱与随手记）→ 编辑 → 归类（含整理模式）→ 搜索 → 删除与撤销 → 导出；覆盖 1440 / 768 / 390px、四套配色与深浅色、输入法、失败保留草稿、版本冲突 409、账号切换。
- 将 `flows.test.tsx` 的长流程用例拆为多个独立用例，使其在默认超时内稳定通过；若仍有必要，只为该文件设置用例级超时，并在提交说明中写明原因。

### 管理员用户列表（O-07，T11）

按 OpenAPI 已有的 `GET /api/v1/admin/users` 实现只读游标分页，复用 active 管理员路由组和 UserPage 字段白名单。前端提供「加载更多」与空列表状态；旧后端返回路由 404 时仅该模块显示「用户列表暂未开放」，401、403 和服务异常按各自语义处理。用户状态写接口另行排期，本版收起禁用/恢复按钮。预算、邀请码和其他管理模块分别处理自身的加载与错误。

### 3.5 接口变更

| 操作 | 方法与路径 | 变化 | 兼容性 |
| --- | --- | --- | --- |
| `exportMyData` | `GET /api/v1/me/export` | 新增 | 新增接口，无影响 |
| 项目决定 | 现有项目决定 PATCH；拟新增 `POST /api/v1/collections/{id}/projects/undo` | 整理提交可选回执、撤销上一步 | T01 更新 OpenAPI、Go 与 Web 类型；已有调用仍可用 |
| `listUsers` | `GET /api/v1/admin/users` | 实现已有契约及分页 | 无字段变更 |

### 3.6 数据变更

计划复用现有表，无新迁移。导出限流沿用 PostgreSQL 限流表，使用独立的用户导出键，并返回实际剩余等待时间。导出单独设置有限的读写时间与取消处理，联调覆盖现有 API 的 15 秒请求和 20 秒写入期限。

## 5. 测试与验收

- **线上修复**：匿名 401、普通账号 403、管理员 200；至少两页合成用户无重漏；模拟旧后端仅列表 404 时预算仍可用。
- **整理**：无关联→手动→撤销、建议→确认→撤销并保留引文、多选原子恢复；另一标签已改动时返回 409，重复撤销不重复写入。
- **后端**：导出只含本人数据；不含回收站内容；Markdown 转换覆盖全部允许的节点与标记；文件名清洗；限流返回 429；客户端断开后停止读取。
- **Web**：整理模式按角色与名称覆盖选择、跳过、撤销、完成态与过期建议提示；导出卡片的下载链接与限流提示。
- **联调**：按 3.4 节清单执行；各需求的验收标准见 ITERATION F-01、F-06、F-10。
