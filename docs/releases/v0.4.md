# v0.4 邀请内测

2026-11-19 · 开发中 · 目标版本 v0.4.0 · M4、O-02、O-03

受邀者拿到管理员分发的邀请码，能用自己的邮箱注册、保存第一条资料、按项目或关键词找回，丢失密码时能重新进入自己的账号。首批按现有计划分发 5 个邀请码，扩大邀请前观察一周的投递失败、验证码重发和恢复情况。

## 起点与交付范围

基线为已发布的 [v0.3.0](https://github.com/st2020-2020/spark/releases/tag/v0.3.0)，schema v7。生产已有 HTTPS、登录、文字和链接收藏、归类与搜索、按账号试用的文字 AI；复用现有额度、迁移、停写备份与恢复验证流程。真实邮件和跨故障域恢复是本轮重点。

| 用户场景 | 本轮行为 | 验收依据 |
| --- | --- | --- |
| 领取邀请并注册 | 管理员预览、导入并自行分发邀请码。收件人申请注册验证码，提交邮箱、验证码、密码和邀请码 | 受控真实邮箱收信；同一邀请码只成功兑换一次；遇投递失败有可理解的重试路径 |
| 找回密码 | 使用找回密码专用验证码；重置成功后重新登录 | 原密码和原会话失效；旧码、过期码和其他用途的码不能重用 |
| 收下并找回 | 登录后保存文字和网址，手动归类，从项目、搜索和回收站找回 | 同一账号刷新可见、另一账号不可见；回收站恢复和导出可用 |
| 安卓继续编辑 | 合并网页对新版客户端的「更多 → 本机草稿」入口；原生 Android 0.2.0 由打包机从现有分支构建 | 普通浏览器与旧 WebView 隐藏原生入口；验收包名、签名一致的覆盖升级及离线草稿 |
| 运维恢复 | 从主机以外的加密副本恢复到干净环境 | 核对恢复点、耗时、账号和收藏归属；邮件任务和旧会话在恢复库重新服务前按恢复规程处置 |

OSS 图片上传仍需满足共享桶的站点来源要求；网页提取需要受控出口，图片理解需要专用生产凭据与独立同意，永久删除需要独立故障域的回执。分别保持现有开关，独立完成条件后再灰度。图片相关搜索在隔离环境验证。日历和灵光重现沿用 v0.5 排期。

## 接口、状态与生产配置

- 沿用 `POST /api/v1/auth/verification`、注册和重置密码接口。202 表示请求已持久受理；60 秒重发间隔、10 分钟有效期及现有 5 次校验尝试限制维持。未开通邮件返回 503，限流返回 429。注册与找回密码分别按用途和规范化邮箱绑定。
- 后端在一个事务内写入挑战、加密后的待发邮件和 River 作业，队列只携带挑战 ID。SMTP Worker 发送前检查当前挑战状态，成功后清除载荷。明确未接收的瞬时失败可在有效期内限次退避；接收结果未知时停止自动重发。迁移 008 支持投递状态；保留 v7 数据。生产使用验证证书的加密连接，发信凭证只读挂载到邮件 Worker。
- 注册和重置表单在更换邮箱时清除原挑战；迟到响应不得覆盖新地址。页面区分受理、等待重发、过期和服务未配置。生产页面不显示开发取码提示。管理员使用现有邀请导入、批次及用户接口。
- 备份沿用逻辑导出，生产恢复目标按 [ROADMAP](../ROADMAP.md) 验证 RPO 15 分钟、RTO 2 小时。每日一次全量转储仅能提供约一天的恢复间隔；独立保存、密钥可恢复性、备份频率及实际容量需一起验收。日备保留目标 30 天，近期恢复点的频率与保留期按实测容量配置。备份失败应得到可处置的反馈。恢复端先隔离邮件和外部任务，核对快照之后的删除回执，防止重发旧验证码或恢复已删除资料。

## 腾讯云个人账号发信

生产接入目标为腾讯云邮件推送的 `SendEmail` 模板 API。2026-03-02 起新开通服务的个人实名认证账号可用 API 发信。建议在 DNSPod 验证专属子域 `notify.stwqy.cloud`，使用 `verify@notify.stwqy.cloud`，注册和重置分别绑定审核通过的模板 ID。服务端仅向本次挑战绑定的一个收件地址发送，模板变量 `code` 为六位验证码。受控 SMTP 演练的证据单独保留，腾讯云投递以受控真实邮箱收件为准。[个人账号公告](https://cloud.tencent.com/announce/detail/2212) · [发送接口](https://cloud.tencent.com/document/api/1288/51034)

| 用途 | 邮件主题 | 建议送审正文 |
| --- | --- | --- |
| 注册 | Spark 注册验证码 | 你正在使用此邮箱注册 Spark。请输入验证码 {{code}}，申请后 10 分钟内有效。请勿向他人透露验证码。如非本人操作，可忽略此邮件。 |
| 找回密码 | Spark 密码重置验证码 | 你正在重置 Spark 账号密码。请输入验证码 {{code}}，申请后 10 分钟内有效。请勿向他人透露验证码。如非本人操作，可忽略此邮件。 |

## 分工与顺序

| 任务 | 原负责人 | 依赖与交付 |
| --- | --- | --- |
| T01 外部资产 | 部署、总控 | 核对发信身份、允许的 SMTP/受控收件箱及异机存储与解密身份。凭证通过受限文件交接。隔离开发可先行 |
| T02 验证码投递 | 后端 | 基于 v7 迁移、River 邮件队列及 SMTP 故障回归；将配置契约给 T03、交互语义给 T07 |
| T03 运行接线 | 部署 | 在 T02 配置契约上接 Compose、预检、健康检查与能力回退；维持旧环境默认关闭 |
| T04 异机恢复 | 部署 | 用临时库验证加密备份、解密、还原与恢复后清理；独立记录真实目的地和可恢复时间窗 |
| T05 容量 | 总控、后端 | 先测基线，再核对候选改动。20 账号各 1,000 条资料，10 客户端、2 后台任务运行 15 分钟；报告保存和搜索 p95（目标均小于 1 秒）、列表、上传完成、并发和资源 |
| T06 安全与依赖 | 总控对接安全审查 | 对集成候选做固定差异审查，关注邮箱滥用、密钥挂载、账户归属与备份身份；查实际依赖告警并处置 |
| T07 邀请与找回交互 | 前端 | 注册、重发、密码找回和管理邀请；复用现有响应式布局。用隔离账号走通注册到收藏找回 |
| T08 Android | 安卓、外部打包机 | 继续使用 `feat/android-mobile-shell`，源码交付点 `df4abdc`；本机不构建 APK。签名、覆盖升级与真机结果独立记录 |
| T09 功能开关 | 部署、总控 | 对照 v0.3 现网，保留文字 AI 范围及额度；在邮件启停、恢复和退版时验证各 Worker 实际状态 |
| T10 整版验收与上线 | 总控、部署 | 用受控账号验注册、收藏、找回与导出。修正后同一候选走 PR、CI、主干标签和公网回测 |

T02、T04、T05、T07 可并行。完成本地投递与页面后联调；真实邮箱与异机存储条件决定对应能力何时可对受邀者开放。证据归入 [ROADMAP](../ROADMAP.md)，用户可体验的范围按实际发布记录。

## 发布与回退

1. 在隔离环境验证 v7 升级、旧数据保留、生产默认关闭、开启邮件后的真实收件和密码重置。容量基准与真实付费外部调用分开。
2. 按 [发布流程](../../CONTRIBUTING.md) 完成独立审阅、三个 CI 检查及维护者合并。部署取不可变标签和完整 SHA，先停写备份并验证恢复，再显式迁移。
3. 公网验证页面、健康、登录和原试用能力。受控收件通过后启用邮件并小范围邀请；遇投递故障可停邮件派发并关闭新申请，已有账户继续登录和收藏。新版本可能已有写入时保留现库，依[部署规程](../../deploy/README.md)处置。
