## 1. 目标与成功标准

让输入不打断思路，让熟练用户更快，让喜欢的内容可以分享出去。

- 不离开键盘即可完成「输入 → 打标签 → 选项目 → 保存」。
- 主要列表操作都可以用键盘完成。
- 分享卡片在四套配色下排版正确，默认不暴露项目与用途。

## 3. 方案设计

### 3.1 标签与输入即标记

- 实现契约已有的 `/tags` 与 `/collections/{id}/tags`；迁移新增 `tags` 与 `collection_tags`（按 DATA.md）。
- 编辑器扩展：输入 `#` / `@` 时弹出联想；选中后生成关联，正文中不保留触发字符；输入法组合期间不触发。
- 用户在新版说明中同意后，AI 可从本账号与材料匹配的已有标签中选择。保留人工增删；旧授权只进行原有文字整理。

### 3.2 分享卡片

- 详情页「生成卡片」：在浏览器内用 Canvas 绘制点阵纸背景、纸条正文、日期印章与小瓶子标志，跟随当前配色；长文截断并注明「节选」。
- 通过系统分享或下载保存，不上传服务器。

### 3.3 键盘与命令面板

- 列表：`J` / `K` 切换，`Enter` 打开，`E` 编辑，`R` 切换已读，`N` 记一条（已实现）。
- 命令面板：搜索收藏、跳转项目、切换配色与明暗；设置页提供快捷键说明。

### 3.4 外观偏好同步

- 用户偏好新增 `palette` 与 `theme` 字段；登录后以服务端为准，本机未登录时沿用本地存储。

## 5. 实施与验收

- 标签和项目存为账号内关联，保留正文协议。输入时取消联想应保留原字符，保存失败应保留正文与选择。按标签找回须使用服务端过滤，计数和分页均遵守账号与回收站边界。
- 分享卡片默认只展示选取的正文、日期与样式。来源网址或项目须由用户主动选择，预览和最终 PNG 使用相同内容；图片上传凭据、附件签名和用途说明不进入产物。
- T01 与 T05 后端先提供增量迁移与契约，前端同步生成类型。T03 与 T04 可先行实施。使用两个合成账号核对标签归属、外观持久化和切换账号；浏览器覆盖中文组合输入、键盘焦点、窄屏触控、分享取消及下载。
- T06 在隔离 PostgreSQL、API、Web 中恢复 v9 样本，验证旧收藏、项目和附件在升级后仍可读取，再用同一候选演练恢复。测试对象和图片只使用合成样本。
- 总控汇总固定提交的实现、审查和验收证据后开 PR。必需 CI 通过并取得维护者人工审核后，从合入主干的提交打正式标签。生产部署先停写备份并验证恢复，再显式迁移和切换；保留已启用的文字 AI、邮件、OSS 资产 Worker 和管理员图片 Worker，核对服务健康、公开静态资源与实际功能。

## 7. v0.6.1 线上功能完整性修复

以已发布的 v0.6.0 为审查基线。独立审查从普通账号和有图片试用资格的管理员两种视角，检查收集、后台处理、人工归类和再次找回的全过程。对发现记录触发条件、用户可见影响、涉及版本和修复后的验证结果，区分代码审阅、隔离环境实测与生产验证。生产尚未开放的网页提取和永久删除仅检查入口是否准确表达可用范围。

首个已确认的问题是图片识别成功后，项目整理仍只使用原有文字材料。用一张合成图片和一个简短标题验收，在标题不能判断项目、图中信息能判断项目时，应自动出现可确认的建议及其图片依据。另用没有匹配项目的样本确认系统允许无建议。已保存的收藏应支持主动重新整理并复用有效的识别结果。

修复需保留人工决定、账号与试用权限、授权撤回和费用上限。联调查验自动触发、重复事件、后台失败和确认后刷新。使用合成图片和受控模型端点验证，不批量重跑历史收藏。正式发布后分别记录线上服务状态和实际验过的交互。

基线实测使用 v0.6.0 的 Web、API、PostgreSQL、River 和受控存储及模型。两条短正文各带一张合成图，一条仅图中有项目线索，另一条无匹配。图片识别和下载都成功，两条均无项目建议。再次整理正例只新增一次文字调用，文字模型仍只收到正文和用途。已保留两条合成收藏的 v10 转储和对应图片，供 v11 验证历史结果的复用。

## 8. v0.6.2 密集图片识别与旧结果恢复

上线的 v0.6.1 在第一段文字输出中途遇到长度上限时，可能收不到任何完整字段。此时详情同时显示“部分识别”和“未识别出有效文字”。已有收藏保留原图，刷新状态只重新读取提取结果。

本次修复优先取得密集图的标题、代表性原文及简短描述，沿用每次调用的预算上限。前端区分正常空结果、截断后仍有可用材料、截断后没有可用材料。已有空截断的附件应能由本人发起一次重新识别，沿用图片独立授权、试用范围、排除规则及共享预算。刷新和发布均不自动重跑旧图。

验收使用合成图和受控模型。分别检查正常完成、在第一个字段及第二个字段中途截断、错误结构、旧记录和重复点击。确认实际可展示的文字能进入已有项目整理流程，并核对调用次数与账本。生产用户图片不作为测试样本。

## 9. v0.6.3 图片模型响应兼容与失败恢复

v0.6.2 上有一条历史图片恢复请求在收到 HTTP 200 后进入 `failed/invalid_model_output`，该次用量已经结算。上次验收使用受控模型返回指定的两个字符串，未检验真实模型能否按照同一约定返回可用的文字。这个错误码不足以还原历史响应，也不能据此判断图片没有内容。

本次使用用户在会话中提供并指定测试的图片副本，对照旧版、最终候选和真实图片模型。验收以详情能显示与图面相符的标题或关键原文、用户能理解的画面信息为准。记录协议形状、是否命中图内线索和结算结果，用户图片、提取正文及凭据不进入仓库。兼容性用例使用合成内容，覆盖有效和无效的响应。

旧版已结算且无可用内容的这条失败记录须有单附件恢复路径。仅由用户在详情显式发起；重复确认、响应丢失、已发送但费用不明均不得引起重复派发。保留历史提取和账本，沿用图片授权、用户与附件归属、共享额度和回收站限制。

## 10. v0.6.4 图片笔记的正文、项目归档与分享

图片笔记应能回答三个问题：图片里有什么、笔记放到了哪里、分享给别人时对方会看到什么。

- **识别与正文**。有可读内容就显示实际文字或画面描述。结果只覆盖部分图片时，以日常语言说明，并可查看原图。每张图的画面描述作为单独的笔记段落，有来源标识，可编辑或移除。保留用户输入、编辑后的内容和已经移除段落的决定。
- **归类**。在本人开启图片理解并接受新版自动整理说明后，优先归入有依据的进行中项目。没有合适项目且能从图片材料辨认出主题时，按主题新建项目并放入笔记。无法判断则留待归类。项目名单、名称、证据和写入都限定当前账号。旧版授权沿用已有建议流程。复用已识别图的结果，不批量重发历史图片。
- **分享**。带图片的笔记生成卡片时默认绘制图片缩略图，可关闭。预览、下载和系统分享使用同一份 PNG。使用当前账号的同源缩略图，输出图像仅携带绘制的像素。图片暂时不可读取时提供可执行的提示。

隔离验收应覆盖已有项目、建立新主题项目、无有效材料、重复交付、人工移除、旧图片与旧授权。用浏览器读取最终分享文件的像素，并在移除图片选项后对照。前后端和数据库使用同一个固定提交，迁移前验证 v13 备份可恢复。
