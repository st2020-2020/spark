## 1. 目标与成功标准

让想法可以持续生长成线索，并把收集入口延伸到浏览网页的现场。

- 一条收藏可以追加续写，形成可回看的思考线索。
- 在电脑浏览器中划词或整页收藏，内容准确（M5 完成标准）。
- 微信渠道形成投入或不投入的书面结论。

## 3. 方案设计（概要）

### 3.1 续写

- 从活跃收藏的卡片或详情点「续写」。新笔记独立保存、可搜索和归类，原笔记的标题、正文和人工决定保持原值。收集框显示来源，预选仍可用的已归入项目；用户可以逐个更改或全部清空，按最终选择保存。没有项目时沿用普通收藏的待归类规则。
- 复用创建收藏的入口与幂等键，新收藏和来源关联一起提交。来源由服务端按当前账号验证，只能关联已存在的活跃收藏，创建以后来源固定。断线重试得到原记录；从两台设备分别追加则保留两条。
- 从任意活跃成员打开详情都能按创建时间及 ID 稳定分页回看整条线索，两条续写指向同一个来源也在同一视图。软删除成员只显示占位，恢复后可重新打开。永久清理后仍能访问其余活跃成员。旧收藏继续通过原入口保存和查看。
- 迁移 v15 → v16，旧收藏各自形成独立线索。创建收藏增加可选 `source_collection_id`。详情时间线通过 `GET /collections/{id}/thread` 分页读取；`follow_up_count` 表示线索中除当前条目以外的活跃成员数，包含同来源的分支。字段与错误响应以 [OpenAPI](../../contracts/openapi.json) 为准。
- 第一批独立上线。联合验收采用两个普通合成账号，手机视口追加、桌面打开同一线索、并发分叉和中间条删除恢复，并检查其他账号无法查看或续写。部署复用正式脚本验证旧库恢复、显式迁移和原有服务健康。

### 3.2 浏览器扩展

- Chrome 和 Edge 使用同一个 Manifest V3 扩展。用户从工具栏收藏页面，或从选区菜单保存选文，可补用途、改项目。保存前展示实际内容；网页提取关闭时保存标题、网址及已选文字。
- 页面访问限于用户操作的当前标签。扩展仅向 Spark 发送待保存数据，使用独立可撤销凭据，权限限定为收集与读取可选项目。断线后复用同一条待保存内容的请求键。验收包括未绑定、撤权后拒绝、切换账号、重复请求以及服务端已保存但响应丢失。
- 第二批从第一批合并后的主干独立开发、验收和发布。先在 Chrome 和 Edge 本地加载验证，再根据发布账号和审核结果安排公开上架。[Chrome 当前标签权限](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab) · [Edge 本地加载](https://learn.microsoft.com/en-us/microsoft-edge/extensions/getting-started/extension-sideloading)

#### 本地加载与首次连接

正式发布后，从该版本的 GitHub Release 下载扩展 ZIP，解压并保留该目录。在 Chrome 打开 `chrome://extensions`，在 Edge 打开 `edge://extensions`，启用开发者模式，点「加载已解压的扩展程序」，选择直接包含 `manifest.json` 的目录。升级时用新版本文件替换该目录内容，在扩展管理页点重新加载。

从工具栏打开「Spark 收集助手」，点「连接 Spark」，在 Spark 网页核对登录账号与两端配对码后确认。回到扩展完成连接，再在需要保存的网页打开扩展检查标题、网址、选文和项目。设备可在 Spark 设置中单独撤销。

#### 第二批接口与交互设计

用户在扩展点「连接 Spark」，在同源 Web 页核对账号、设备和两端的配对码，再确认授权。扩展生成随机兑换凭证，网页只接收其摘要。授权 5 分钟有效，兑换时复查批准会话及账号状态，并在事务中一次性消费。只有扩展收到有效期 7 天的访问令牌。设置中可单独撤销设备，重置密码沿用全部会话撤销流程。兑换响应丢失时可重新绑定，设置中仍可撤销此前的设备会话。

| 入口（均在 `/api/v1` 下） | 能力与范围 |
| --- | --- |
| `POST /extension/grants` | Web 会话和同源 CSRF 校验后确认本次配对。 |
| `POST /extension/token` | 用原兑换凭证换取扩展令牌、到期时间和供用户辨认的账号信息。 |
| `GET /extension/session`、`DELETE /extension/session` | 查看或断开当前扩展会话。普通 Web 路由仅接受 Web 类型会话。 |
| `GET /extension/projects` | 按账号搜索、分页返回可选的进行中项目，只包含 ID 与名称。 |
| `POST /extension/collections` | 创建收藏并返回 ID，支持网页标题、HTTP(S) 来源、纯文本选区、用途、选定项目和客户端生成的收藏 ID。复用已有收藏事务、预算与幂等逻辑，在服务端校验项目归属和可用状态，拒绝未约定字段。 |

扩展在发送前显示目标账号、标题、网址、实际选文及项目。标题上限 200 字符，网址上限 4,096 字符，选文与用途合计上限 50,000 字符。超限时保留输入，指明需要缩短的字段；已失效的项目提示重新选择。没有选文时保存标题及网址。

首次提交前按站点和账号保存请求快照、收藏 ID 和幂等键。提交结果未知时，同账号用原快照重试；超出幂等保留期后提供按原 ID 到 Web 核对的入口。换账号后隔离原草稿，用户可回原账号继续或主动清除。扩展后台只向固定 Spark 站点发送令牌，页面及内容脚本无法读取令牌，草稿与凭据均不进入浏览器同步存储。

第二批验收分别覆盖失效或已消费的配对、授权后重置密码、撤权后使用原键重试、成功响应丢失、同名账号标签下用账号 ID 隔离草稿、跨账号项目和未知字段拒绝。使用真实浏览器加载扩展与隔离 Spark API 验证。

## 7. v0.7.2 扩展保存回执与网页归档（开发中）

v0.7.1 在长表单上方显示保存回执，用户在底部点击保存后容易错过。扩展通过共用创建入口持久化收藏，网页标题存为人工标题，只有选文进入正文。文字整理读取正文、用途和已授权的图片材料，单独的网页标题无法提供归类线索。普通文字项目匹配只写待确认建议。以上是线上版本的代码行为，单条收藏的实际运行状态以其回执与整理记录为准。

- 点击保存立即在当前视口反馈。收到成功回执时显示可辨认的已保存收藏，提供直接打开入口。连接中断且结果未知时保留原请求供核对与重试。收藏写入成功和后台完成项目归档分别展示。
- 扩展保存网页时，按用户授权使用其核对过的标题、选文及用途。在有准确材料支持时优先归入已有项目；没有匹配但主题明确时沿用简短项目名和按账号复用规则。用户已选项目或已作人工决定时尊重其选择。材料不足时保留收藏并给出可执行提示。
- 网页归类沿用平台里的文字整理授权入口，向用户披露新增材料和用途。已有授权维持其原范围。更新授权本身不触发历史整理；用户可以在某条旧网址收藏详情核对内容，再主动归档这一条。来源未知的旧网址也可由用户选中处理，界面只在来源可证实时标记为扩展收藏。
- 扩展的权限和保存回执维持 v0.7.1 契约。扩展提供「查看收藏」入口，平台详情负责呈现等待授权、整理中、已归入已有项目、已创建项目或暂无匹配。若只有网址，提示补标题或用途，保留手选项目入口。
- 验收覆盖无选文但标题明确、选文命中项目、证据不足、人工选项目、旧授权、断线原键重放及跨账号。使用隔离环境和合成网址；着重核对项目页实际归属、模型调用次数与长表单底部的成功回执。旧收藏仅在用户主动操作时重新整理。
