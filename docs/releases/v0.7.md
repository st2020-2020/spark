## 1. 目标与成功标准

让想法可以持续生长成线索，并把收集入口延伸到浏览网页的现场。

- 一条收藏可以追加续写，形成可回看的思考线索。
- 在电脑浏览器中划词或整页收藏，内容准确（M5 完成标准）。
- 微信渠道形成投入或不投入的书面结论。

## 3. 方案设计（概要）

### 3.1 续写

- 从活跃收藏的卡片或详情点「续写」。新笔记独立保存、可搜索和归类，原笔记的标题、正文和人工决定保持原值。收集框显示来源，预选仍可用的已归入项目；用户可以逐个更改或全部清空，按最终选择保存。没有项目时沿用普通收藏的待归类规则。
- 复用创建收藏的入口与幂等键，新收藏和来源关联一起提交。来源由服务端按当前账号验证，只能关联已存在的活跃收藏，创建以后来源固定。断线重试得到原记录；从两台设备分别追加则保留两条。
- 从任意活跃成员打开详情都能按创建顺序分页回看整条线索，两条续写指向同一个来源也在同一视图。软删除成员只显示占位，恢复后可重新打开。永久清理后仍能访问其余活跃成员。旧收藏继续通过原入口保存和查看。
- 第一批独立上线。联合验收采用两个普通合成账号，手机视口追加、桌面打开同一线索、并发分叉和中间条删除恢复，并检查其他账号无法查看或续写。部署复用正式脚本验证旧库恢复、显式迁移和原有服务健康。

### 3.2 浏览器扩展

- Chrome 和 Edge 使用同一个 Manifest V3 扩展。用户从工具栏收藏页面，或从选区菜单保存选文，可补用途、改项目。保存前展示实际内容；网页提取关闭时保存标题、网址及已选文字。
- 页面访问限于用户操作的当前标签。扩展仅向 Spark 发送待保存数据，使用独立可撤销凭据，权限限定为收集与读取可选项目。断线后复用同一条待保存内容的请求键。验收包括未绑定、撤权后拒绝、切换账号、重复请求以及服务端已保存但响应丢失。
- 第二批从第一批合并后的主干独立开发、验收和发布。先在 Chrome 和 Edge 本地加载验证，再根据发布账号和审核结果安排公开上架。[Chrome 当前标签权限](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab) · [Edge 本地加载](https://learn.microsoft.com/en-us/microsoft-edge/extensions/getting-started/extension-sideloading)

### 3.3 微信渠道评估

- 输出评估文档：服务号资质与认证主体、消息接口对文章与图片的支持、账号绑定与解绑、数据处理与留存、成本。结论写入 DECISIONS。
