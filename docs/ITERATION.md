## 1. 产品定位与迭代原则

### 1.1 定位

Spark 帮助个人把一闪而过的文字、网址和图片先可靠地收下来，再归到正在进行的项目里，需要时快速找回。

产品的主线是 **「收集 → 归类到项目 → 找回」**。区别于单纯的随手记录：每条资料最终都应服务于某个具体的项目或目的。迭代优先投入能加强这条主线的能力，不追求功能数量。

视觉与交互概念为「灵光手帐」：点阵手帐纸画布、按天排列的日志、纸条式卡片、项目纸胶带色、收集灵光的小瓶子。新功能应沿用这套语言，详见 [Web 视觉设计](design/WEB-VISUAL.md)。

### 1.2 迭代原则

1. **原文优先，慢操作异步。** 先可靠保存原始内容，提取、识别、整理在后台进行，失败不影响已保存内容。
2. **人工决定优先。** 用户对归类、标签的确认、移除与忽略，后续自动处理必须尊重。
3. **不显示假功能。** 后端未接通的能力不展示可点击入口，不用模拟结果冒充真实能力。
4. **最少数据，明确授权。** 涉及第三方服务（模型、识别、消息平台）时，只发送完成任务所需的最少数据，并沿用现有知情同意流程。
5. **轻量可完成。** 每次迭代优先选择能在一个批次内闭环、可验证的切片，而不是一次铺开大功能。
6. **手机与电脑同等可用。** 新交互须同时给出手机与电脑方案，触控目标、键盘可达、减少动效偏好都要覆盖。

## 4. 需求详述

每项按「背景 → 用户故事 → 方案要点 → 范围边界 → 依赖 → 验收标准 → 度量 → 风险与待决」描述。

### F-01 整理模式（P0）

**背景。** 收集很容易，归类却总被推迟。待归类越积越多，项目就失去意义，找回也会变难。现有待归类页是长列表，在手机上逐条选择项目操作成本高。

**用户故事。** 作为用户，我想用几分钟把待归类的收藏一张张过一遍，每张只需轻点一次就归到项目里，让收件箱保持清爽。

**方案要点。**

- 入口：待归类页标题区的「开始整理」，以及收件箱在存在待归类资料时的一句轻提示。
- 界面：全屏卡片堆，一次只展示一张纸条（正文、来源、用途、AI 建议依据）。卡片下方一排项目纸胶带，AI 建议的项目排在最前，并带「建议」标识。
- 操作：
  - 点项目胶带：加入该项目（include），卡片飞入对应胶带，下一张补位；可多选后再确认。
  - 「跳过」：本次不处理，卡片移到队尾。
  - 「不属于任何项目」：保留在收件箱，不再出现在本轮整理中（仅本地会话状态，不新增服务端状态）。
  - 「撤销」：撤回上一步，调用 reset 或 exclude 恢复原状。
- 手机：支持左滑跳过、右滑打开项目选择；所有手势都有等价按钮。电脑：数字键 1–9 选项目，S 跳过，Z 撤销，Esc 退出。
- 完成态：本轮清空后显示瓶子装满的插画与本轮归类数量，提供「返回收件箱」。
- 并发与冲突：沿用 `decision_version` 与安全决定流程，处理过期建议的提示与刷新。

**范围边界。** 不新增批量接口，逐条调用现有决定接口；不在本模式内编辑正文；不改变自动整理规则。

**依赖。** 前端为主；可选：后端为待归类列表提供 `total`，用于显示进度（契约中 `has_suggestion` 查询已返回 total，`unclassified` 是否返回需确认）。

**验收标准。**

- 连续整理 20 条，每条一次点击即可完成归类，界面无卡顿，进度准确。
- 撤销可恢复上一条的项目关联，刷新后状态一致。
- 他处已处理的建议在整理中出现时，给出同步提示并跳过，不产生错误关联。
- 手机 390px、平板 768px、电脑 1440px 可用；仅键盘可完成全部操作；减少动效偏好下无飞入动画。

**度量。** 待归类存量的周变化；进入整理模式后的完成率；单条平均处理时长。

**风险与待决。** 「不属于任何项目」是否需要服务端持久化（例如「已查看、无需归类」标记），以免下次整理反复出现，需在体验后决定。

### F-02 图片收藏与文字识别（P0）

**背景。** 截图是手机上最常见的收集方式。「截图用于参考交互」是 PRODUCT 的验收场景之一，目前尚不支持。

**用户故事。** 作为用户，我想把截图、照片和文字一起保存，并能通过图片里的文字搜到它。

**方案要点。**

- 收集框支持选择、粘贴、拖拽图片，每条最多 9 张，每张 5 MiB（沿用 WEB.md 约定），逐张显示上传进度、失败原因、重试与移除。
- 卡片：单图显示为圆角大图；多图显示为九宫格缩略图，点击进入详情查看。
- 详情：图片可放大浏览；识别出的文字折叠在「图片文字」中，可复制。
- 搜索：识别文字参与关键词检索，命中时片段标注「图片文字」。
- 安全：OSS 私有存储，短时授权访问；上传校验大小、真实类型与归属。

**范围边界。** 首期不做图片编辑与标注，不做视频。

**依赖。** 阿里云 OSS 配置、OCR 服务选型与预算（见 ROADMAP「后续接入所需信息」）；后端上传、校验、提取任务；契约已预留。

**验收标准。** 按 ROADMAP M2/M3 的完成标准；补充：弱网下上传失败可单张重试；识别失败不影响收藏保存；图片文字搜索可命中。

**度量。** 含图收藏占比；图片文字搜索命中次数。

### F-03 链接预览（P0）

**背景。** 网址收藏目前只在卡片上显示链接标记，看不出是哪篇文章，找回时依赖正文。

**用户故事。** 作为用户，我保存一个网址后，希望卡片上直接看到网页标题、站点和简短摘要。

**方案要点。**

- 保存后后台抓取网页标题、站点名、正文摘要（M3 网页正文提取），抓取中显示「正在获取网页信息」。
- 卡片在正文下方显示链接小卡：站点名、标题，以及两行摘要；点击在新标签页打开原网页。
- 抓取失败时只保留网址，不显示错误占位；详情中可手动「重新获取」。
- 摘要与正文参与搜索。

**范围边界。** 不展示第三方网页图片，避免隐私与版权问题，后续另行评估；不做网页快照存档。

**依赖。** 后端网页正文提取（含 SSRF 防护、重定向校验、大小与超时限制）；`CollectionSummary` 需增加可展示的来源标题与站点字段（契约变更）。

**验收标准。** 常见中文资讯与技术博客的标题提取准确；内网地址与非 http(s) 协议被拒绝；抓取超时不阻塞保存；失败后可手动重试。

**度量。** 网址收藏的预览成功率；详情打开率变化。

### F-04 灵光重现（P1）

**背景。** 资料存进去后很少再被看到。适时让旧资料回到眼前，才能真正被用上。

**用户故事。** 作为用户，我希望每天打开时能看到几条值得重新看一眼的旧收藏，尤其是还没归类的，以及和正在做的项目相关的。

**方案要点。**

- 收件箱顶部的「今日重现」区，每天最多 3 张纸条，可横向滑动；没有合适内容时不显示该区。
- 选取规则（按优先级）：
  1. 7 天以上仍待归类的资料；
  2. 属于进行中项目、30 天以上未打开的资料；
  3. 往年同一天的资料（附「一年前的今天」字样）。
- 每张提供「归类 / 打开 / 今天不再显示」；可在设置中关闭整个区域。
- 选取在服务端完成，同一天结果稳定，不因刷新变化。

**范围边界。** 不推送通知（后续评估），不做跨用户推荐。

**依赖。** 新增接口（例如 `GET /me/resurface`），基于现有字段计算；需记录「今天不再显示」的轻量状态。

**验收标准。** 同一天多次打开结果一致；只返回本人资料；已删除资料不出现；关闭开关后不再请求。

**度量。** 重现卡片的点击率与归类率；被重现资料后续的打开次数。

**风险与待决。** 「打开时间」需要后端记录最近查看时间（当前只有已读时间），需评估是否用 `read_at` 近似。

### F-05 灵光日历（P1）

**背景。** 收件箱已按天排列，适合加一个全局的时间视角：哪天记得多、某段时间在想什么。

**用户故事。** 作为用户，我想看到最近几个月每天记录的疏密，并点某一天直接跳到那天的日志。

**方案要点。**

- 桌面侧栏底部放一张月历热力图，颜色深浅表示当日收藏数（使用当前配色主色的几个透明度档位），手机放在「更多」面板顶部。
- 点击某天：收件箱按当天筛选，日期印章高亮，标题区显示「11月18日」并可一键清除。
- 鼠标悬停或长按时显示「11月18日 · 5 条」。

**范围边界。** 只统计未删除的收藏，不做连续打卡奖励。

**依赖。** 后端实现 `created_from` / `created_to` 筛选（契约已有），新增按日计数接口（按用户本地时区，或由前端传入时区）。

**验收标准。** 计数与筛选结果一致；跨时区、跨月边界正确；热力色在四套配色与深色模式下都可分辨，同时提供文字数量，不只依赖颜色。

**度量。** 日历点击次数；按日浏览后的打开率。

### F-06 数据导出（P1）

**背景。** 个人资料产品需要让用户确信数据是自己的、随时能带走。这也是邀请内测阶段建立信任的基础。

**用户故事。** 作为用户，我想把全部收藏和项目导出成通用格式保存在自己电脑上。

**方案要点。**

- 设置页「导出我的数据」：选择格式（Markdown 压缩包，或 JSON），提交后生成，完成后提供短时下载链接。
- Markdown：每个项目一个文件夹，每条收藏一个文件，包含正文、用途、来源网址、创建时间、项目；待归类单独一个文件夹。
- JSON：完整字段，便于以后导入；附件以链接或附件文件夹提供（随 F-02）。

**范围边界。** 首期不做导入；不导出 AI 调用记录与额度账本。

**依赖。** 后端异步导出任务与私有存储；下载授权短时有效且限定本人。

**验收标准。** 导出内容与线上一致；他人无法下载；大账号导出不阻塞服务；失败可重试。

### F-07 输入即标记：`#` 标签、`@` 项目（P1）

**背景。** 现在选择项目要点工具栏里的文件夹按钮，会打断输入；标签能力尚未接入。

**用户故事。** 作为用户，我想边打字边用 `#主题` 打标签、用 `@项目名` 指定项目，不离开键盘。

**方案要点。**

- 输入 `#` 弹出标签联想（已有标签 + 新建）；输入 `@` 弹出项目联想，选中后在正文下方生成纸胶带，正文中不保留 `@` 文本。
- 标签在卡片上显示为小号文字标签，与项目胶带区分；侧栏增加「标签」分组（可折叠）。
- 中文输入法组合期间不触发联想；Esc 关闭联想并保留已输入字符。

**范围边界。** 标签不嵌套；不做标签颜色自定义。

**依赖。** 标签后端（契约已有 `/tags` 与 `/collections/{id}/tags`）；内容协议是否需要标签节点需评估，倾向于不进正文、只存关联。

**验收标准。** 键盘可完成选择；联想结果仅含本人数据；输入法场景无误触发；AI 整理优先使用用户已有标签（PRODUCT 已有规则）。

### F-08 续写（P1）

**背景。** 一个想法常常在几天后有新的补充。修改原文会丢失思考的过程，另记一条又失去了关联。

**用户故事。** 作为用户，我想在一条旧收藏下面追加新的想法，形成一串可以回看的思考线索。

**方案要点。**

- 卡片与详情提供「续写」，打开收集框并标明「续写自：……」；保存后两条互相关联。
- 详情页展示完整线索（按时间排列的纸条串）；卡片显示「有 2 条续写」。
- 续写是独立收藏，可单独归类、搜索与删除；删除中间一条时保留其余关联。

**范围边界。** 不做双向任意链接与图谱视图（后续评估）。

**依赖。** 数据模型新增收藏间关联及版本语义；契约、迁移与删除生命周期设计（需同步 DATA.md）。

**验收标准。** 关联只能在本人收藏之间建立；回收站与恢复后关联正确；搜索结果可跳转到线索上下文。

### F-09 分享卡片（P2）

**用户故事。** 作为用户，我想把一条喜欢的收藏生成一张好看的图片，发给朋友或保存到相册。

**方案要点。** 详情页「生成卡片」：手帐纸背景、纸条正文、日期印章、小瓶子标记，跟随当前配色；可选是否显示来源与项目；在浏览器本地生成 PNG 下载或调用系统分享。不上传服务器。

**验收标准。** 长文自动截断并注明「节选」；中文排版不溢出；隐私默认不显示项目与用途。

### F-10 添加到主屏幕（P2）

**用户故事。** 作为手机用户，我想像打开应用一样从桌面图标打开 Spark。

**方案要点。** 提供 Web 应用清单与图标（小瓶子标志，四套配色共用主色版本），全屏启动、启动背景色与当前配色一致；首期不做离线缓存，避免与草稿和会话策略冲突，离线能力随 M6/M7 设计。

**验收标准。** iOS 与 Android 主流浏览器可添加；启动后安全区、底部悬浮坞位置正确。

### F-11 键盘操作与命令面板（P2）

**方案要点。** 列表中 J/K 切换纸条，Enter 打开，E 编辑，R 标为已读或未读，N 记一条（已实现）；⌘/Ctrl+K 由「聚焦搜索」升级为命令面板，可搜索收藏、跳转项目、切换配色。在设置页提供快捷键说明。

**验收标准。** 输入状态与输入法组合期间不触发；焦点可见；与浏览器和读屏快捷键不冲突。

### F-12 浏览器扩展（P1，ROADMAP M5）

**方案要点。** 划词或整页收藏，带入网页标题与网址，可补一句用途、选项目；复用随手记界面风格；登录态与 Web 会话分离，使用独立的受限凭据。

**依赖。** 扩展发布渠道、收集接口的授权方式设计。具体以 M5 排期为准。

### F-13 微信转发收藏（待评估）

**背景。** 国内用户大量阅读发生在微信内，转发到 Spark 能显著降低收集门槛。

**待评估事项。** 服务号资质与认证主体；消息接口对文章链接、图片的支持范围；账号绑定与解绑流程；消息内容的最少数据处理与留存。评估结论确定后再拆解需求。

## 7. 度量体系

内测期间建议只采集聚合指标，不记录内容本身，采集方案须先经隐私评估并告知用户。

| 层级 | 指标 | 定义 |
| --- | --- | --- |
| 北极星 | 每周被用上的收藏数 | 一周内被归类到项目、被打开详情或被搜索命中后打开的收藏数 |
| 收集 | 人均周收藏数；各入口占比 | 收件箱、随手记、手机分享、扩展等入口 |
| 归类 | 待归类存量与周变化；AI 建议确认率 | 确认数 ÷（确认 + 忽略） |
| 找回 | 搜索后打开率；无结果搜索占比 | 用于评估检索质量 |
| 留存 | 次周与第四周留存 | 以有收集或打开行为为活跃 |
