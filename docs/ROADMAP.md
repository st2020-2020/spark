- 联调提交 `cd86fe6` 从 v10 样本库升级 v11 后，两个独立浏览器会话验证了跨设备草稿冲突、旧图片手动整理和待确认列表实时更新。管理员更新授权后，匹配样本的建议带有图片文件名和原文引文，确认后刷新仍为已确认。另一张图片明确显示本轮使用图片、无匹配项目。这次浏览器验收没有覆盖后续新增的纯图草稿等提交，也没有发送生产用户数据。

### 容量基线

在独立 OrbStack Compose 项目对 `19ae593` 的服务端（与 v0.3.0 相同）持续施加 15 分钟负载。PostgreSQL 17.6 预置 20 个账号各 1,000 条合成收藏及修订。10 个并发客户端轮换账号，每次请求后间隔 1 秒；通过 HTTP 调用真实 API 路由，River 在同一时间最多处理两个资产任务。对象存储使用受控 HTTP 服务。测试进程限 2 核、2 GiB，数据库限 2 核、1 GiB。耗时包含读取响应，搜索与列表均核对返回 20 条。

| 操作 | 每轮成功请求 | v0.3 基线 p95 | v8 候选 p95 |
| --- | ---: | ---: | ---: |
| 保存文字收藏 | 2,800 | 25.2 ms | 23.8 ms |
| 关键词搜索 | 2,950 | 30.3 ms | 29.9 ms |
| 收藏列表 | 2,940 | 21.7 ms | 20.5 ms |
| 提交上传完成（202） | 150 | 11.3 ms | 10.5 ms |

使用相同数据规模、负载和资源限制，对升级依赖后的 v8 服务端（`b87f48f`）另测 15 分钟。两轮各有 150 条上传随后全部校验为 ready，观察到资产校验并发数达到 2，记录的失败数为 0。基线数据库内存采样 98–117 MiB，包含 API、Worker 和客户端的测试进程采样 53–132 MiB。两项 p95 均达到 1 秒目标。以上为单机隔离基线，未测生产公网延迟、SMTP 或真实 OSS 耗时。验后已回收本轮容器和网络。

## 自动整理评测

自动关联精确率按正确自动关联数除以全部自动关联数计算，目标至少 90%；同时报告应关联资料中被正确自动关联的覆盖率。无自动关联时精确率记为无有效结果。样本数随内测增长，分输入类型报告结果。

对 OCR 记录关键文字能否找回，对摘要记录是否存在材料之外的事实，对项目理由记录是否能回指实际输入。误关联按内容提取、候选遗漏、模型判断和策略应用分别排查。
