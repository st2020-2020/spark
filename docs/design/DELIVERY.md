# 开发分工、部署与验收

交付基线 v1。阶段依赖以 [ROADMAP](../ROADMAP.md) 为准，首发完成条件覆盖 M0 至 M4。

## 接手任务清单

| 任务 | 输入依赖 | 主要产物 | 验收证据 |
| --- | --- | --- | --- |
| 工程与契约 | HANDOFF、OpenAPI、内容 Schema | 独立 server module、Web 工程、客户端生成、开发环境 | 本地运行命令、契约校验、生成客户端编译 |
| 账号与管理 | DATA、API | 注册、会话、邮件、邀请码导入与兑换、用户状态 | 并发兑换、验证到期、禁用、找回密码测试 |
| 项目与收藏 | 账号、内容协议 | 项目生命周期、收藏 CRUD、版本、关联、回收站 | 双用户隔离、冲突和幂等测试 |
| 附件 | 收藏契约、OSS 配置 | 临时上传、最终对象校验、授权与清理 | 覆盖重放、超时、删除及孤立对象测试 |
| 自动整理 | 收藏、任务队列、模型/OCR | 分阶段任务、结构化结果、关联策略、预算 | 故障注入、标注集、成本及耗时记录 |
| Web | OpenAPI、WEB | 手机及电脑完整流程 | 浏览器关键路径、错误态、中文输入与可访问性验证 |
| 搜索 | 内容及提取结果 | 字面检索、筛选、分页、命中片段 | 中文/OCR 数据集与性能结果 |
| 部署与运维 | 可构建应用、正式配置 | 镜像发布、迁移、监控、备份、恢复流程 | 发布回退及空环境恢复演练 |

共享接口文件变更前与使用方核对。多个 agent 在同一工作空间工作时，任务开始记录文件范围，提交前核对实际差异，保留其他任务进行中的内容。

## 环境配置

| 配置组 | 必须提供或选定的信息 | 消费方 |
| --- | --- | --- |
| 应用 | 环境名、正式 Origin、会话秘密、验证码与邀请码摘要秘密、CSRF 配置 | API |
| PostgreSQL | 地址、数据库、应用账号、迁移账号、连接池、TLS | API、Worker、迁移任务 |
| 邮件 | 服务商、已验证发件地址、模板、API 凭证、发送限制 | 邮件任务 |
| OSS | 国内地域、Endpoint、临时与最终对象前缀、Bucket、RAM 权限和凭证来源、CORS | API、Worker |
| AI/OCR | 服务商、模型、接入地址、存储与推理地域、凭证别名、价格版本、超时和限额 | Worker |
| 备份 | 独立桶或存储、备份身份、加密密钥、保留周期和删除清单位置 | 备份与清理任务 |
| 诊断 | 日志保留、错误告警目的地、外部可用性检查 | 运维 |

开发、测试、预发布与生产使用独立数据库和附件前缀或桶，实例可以按资源情况分阶段建立。配置模板仅保存变量名和非秘密默认值，凭证通过部署秘密配置注入。用户资料与模型原文从一般日志排除，必要诊断经授权读取业务存储。

本工作空间的本机测试部署统一在 OrbStack 内通过 Docker Compose 启动 Web、API 和 PostgreSQL，宿主机只通过映射端口访问服务。镜像拉取或容器运行受阻时排查该环境，不在宿主机另建 PostgreSQL、API 或 Web 服务作为替代。开发库与自动测试库隔离；迁移既有本机测试资料时保留备份，使用逻辑导出与恢复，不把 macOS PostgreSQL 数据目录直接挂载给 Linux 容器。

## 单机部署方案

腾讯云 4 核 4GB 初期运行 Caddy、API、Worker 和 PostgreSQL。前端静态文件随版本构建产物部署，API 与 Worker 共享代码版本并独立限制资源。初始 API 连接池上限建议 10，Worker 上限 5、后台并发 2，结合压测调整。

公网入口为 HTTPS，数据库和 Worker 位于私有容器网络。抓取网页的网络出口限制内网和元数据地址，OSS 与模型调用使用各自受限身份。腾讯云访问阿里云 OSS 按跨云路径测试连通性、时延和流量费用。

健康检查分为 live 和 ready。live 反映进程响应，ready 检查数据库及所需迁移版本。模型暂时故障通过任务告警表达，应用保持收集能力。日志按大小和时间轮转，磁盘余量、数据库连接和任务等待时间设告警。

## 发布与回滚步骤

1. CI 执行编译、契约验证、关键测试和依赖检查，生成带提交标识的镜像及前端产物。
2. 在预发布环境应用向后兼容迁移，执行注册、保存、上传、搜索和整理冒烟测试。
3. 生产先验证最近备份，串行执行迁移任务，再启动新 API 与 Worker。记录镜像摘要、迁移版本和模型配置版本。
4. ready 通过后切换 Caddy 上游或更新服务，验证会话、真实读写和任务推进。4GB 主机若不足以双实例运行，明确安排短暂发布窗口并测量实际中断。
5. 应用失败时切回上一镜像和前端产物，数据库保持可兼容结构。破坏性迁移通过独立变更及恢复流程处理。

Worker 停止时停止领取新任务，给已有任务有限完成窗口，超时由队列租约恢复。API 停止前停止接收新连接并等待正在提交的事务结束。

## 测试用例矩阵

| ID | 场景 | 预期 |
| --- | --- | --- |
| AUTH-01 | 两请求同时兑换一次性邀请码 | 只创建一个账号和一次兑换，另一请求失败，事务无残留 |
| AUTH-02 | 验证码过期、超次数或用途不符 | 拒绝消费，邀请码次数保持正确 |
| AUTH-03 | 禁用账号、重置密码、撤销会话 | 旧会话失效，后台访问与上传授权被拒绝 |
| AUTH-04 | 重复 CSV 行、已有代码、并发导入 | 预览显示行错误，提交阶段唯一约束保证整体结果 |
| ISO-01 | A 用户使用 B 的项目、收藏、附件及 OCR ID | 查询或写入均按不可访问处理 |
| ISO-02 | 搜索与后续向量检索含其他用户相似资料 | 结果范围始终限当前用户 |
| SAVE-01 | 提交已成功但响应丢失，重试相同幂等键 | 返回原资源，无重复收藏或任务 |
| SAVE-02 | 相同幂等键不同正文 | 409 idempotency_mismatch |
| SAVE-03 | 两设备基于同一内容版本编辑 | 一个成功，另一个 409，草稿可保留 |
| SAVE-04 | 旧客户端提交未知富文本节点 | 422，保留已有内容和客户端草稿 |
| OSS-01 | 声明小文件但实际超限或魔数错误 | 最终确认拒绝，清理临时对象 |
| OSS-02 | 上传确认后重放原临时 PUT URL | 最终附件内容保持已校验版本 |
| OSS-03 | 上传成功后用户离开、确认重复、绑定与清理竞争 | 状态可恢复，孤立对象按期回收，已绑定对象保留 |
| AI-01 | 进程在提取、模型返回、写回各阶段退出 | 队列恢复，原文完整，结果应用幂等 |
| AI-02 | 模型运行中改正文或关闭 AI | 旧运行失效，保护新内容与偏好 |
| AI-03 | 模型运行中用户移除关联 | rejected 决定保留，自动处理无法重新加入 |
| AI-04 | 提示注入、错误项目 ID、无效 JSON、无引用材料 | 输出验证拦截或降级，拒绝跨用户操作 |
| AI-05 | 平台或用户预算边缘并发调用、供应商超时 | 预留受限，uncertain 计入预算，保存继续成功 |
| AI-06 | 无项目或没有匹配项目 | 正常完成整理并进入待归类 |
| FETCH-01 | 内网、IPv6、元数据、DNS 变化及恶意重定向 | 请求被限制，原网址保留 |
| SEARCH-01 | 中文、英文、OCR 文字、SQL 通配字符 | 按约定字面语义返回，匹配片段正确 |
| SEARCH-02 | 并发新增时分页、筛选改变后复用游标 | 分页稳定，不合法游标被拒绝 |
| DELETE-01 | 删除期间 AI 返回、恢复、到期清理 | 生命周期和结果写回一致 |
| DELETE-02 | 删除后恢复旧备份 | 重放删除清单，相关内容无法重新出现 |
| UI-01 | 手机键盘、中文输入法、网络中断和刷新 | 操作可达，草稿和保存状态真实 |
| RESTORE-01 | 干净环境恢复数据库、附件关联和配置 | 数据核对通过，记录实际 RPO/RTO |

单元测试覆盖校验与纯逻辑，数据库集成测试使用真实 PostgreSQL，附件测试包含真实 OSS 集成和故障适配器。端到端验证在浏览器中完成。模型评测与接口确定性测试分开报告。

## 性能与上线验收

按 ROADMAP 的 20 用户、每人 1,000 收藏、10 并发客户端、2 后台任务持续 15 分钟测量。文本保存和搜索 p95 目标各小于 1 秒，记录错误率与实际资源，报告模型调用的独立时延与费用。

初次上线需要提供实际运行命令、数据库迁移清单、服务配置清单、成功备份、恢复演练、关键用例结果和已知限制。自动关联评测同时报告精确率目标 90% 的达成情况与覆盖率，模型/OCR 真实账号和配置在该阶段确定。

正式域名、邮件发件身份、OSS 权限、模型地区和预算属于集成输入，开发基础模块可先推进。上线日期和可用性承诺依据完成结果与容量实测确定。

## 多端后续交接

M6 将本地旧 Entry 导入为 Collection，按本地库实例标识与原条目 UUID 保存导入映射，实现重复导入安全。附件导入失败可续传，逐条核对原文、时间和图片，成功导入后用户能在 Web 搜索找回。

同步具体契约在 M6 增补，沿用 DATA 的用户内变更序号、内容版本、人工决定和删除墓碑。验收包括乱序请求、断网、账户切换、游标过期、旧版本内容和删除后离线编辑。
