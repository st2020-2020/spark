# 自动整理与项目关联详细设计

目标是将用户保存的材料整理为可浏览、可检索、可关联的收藏。用户原始内容、成功提取材料和 AI 推断分别持久化，展示时标明来源。

## 平台提供 AI（拟实施）

在线客户端只调用 Spark 的收藏、整理状态和人工决定接口。供应商账号、密钥、模型、费用与故障切换由平台管理。用户可控制自己的资料是否交给 AI 处理，包括排除单条收藏；使用时无需选择模型或申请密钥。启用处理时说明发送哪些资料、用途与第三方处理范围。现有数据库的 `ai_enabled` 默认为 false；内测可在一次明确同意后自动整理新收藏，旧资料通过显式重整进入队列。

**首批交付。** 对有文字或用途说明的收藏，用一次非流式文本请求生成标题、必要时的摘要，以及至多一个带原文依据的项目建议。项目少时按账号取活动项目，超出上下文上限时用名称、描述和关注点筛选。模型可返回空候选。裸链接缺乏内容时只保存，网页正文、OCR、标签和自然语言检索分别扩展。首批只提供建议，由用户确认或忽略。

**服务边界。** 收藏服务在保存事务中通过 River 入队。独立 Go Worker 复用 PostgreSQL，按账号、版本读取必要材料并构造请求。组织逻辑依赖一个面向文本生成的调用接口，输入为截断后的材料、任务输出约束、输出长度上限和截止时间，返回结构化内容、实际模型标识、可用的 token 用量及规范化错误。模型没有数据库访问权、工具或任意 URL 访问能力。返回内容先按共享 Schema 和原文引用验证，再按下文竞争规则写回。浏览器和移动端无需接触模型协议。桌面离线整理可独立运行，未来联网时复用 Spark 业务 API。

**供应商接入。** 优先验证 [yetone/magpie](https://github.com/yetone/magpie/tree/4d79bebfa71996935d1262d3690cc19d9f26840c) 的 Docker 网关。该版本采用 [MIT 许可](https://github.com/yetone/magpie/blob/4d79bebfa71996935d1262d3690cc19d9f26840c/LICENSE)，提供协议转换、供应商路由、网关鉴权和独立 Web 管理入口，详见[官方手册](https://github.com/yetone/magpie/blob/4d79bebfa71996935d1262d3690cc19d9f26840c/docs/reference.md)。Spark Worker 通过私有 Compose 网络使用固定的 Chat Completions 文本接口。首批平台配置仅包含一个主模型和一个经验证的备用模型，每条路由声明输出模式、上下文与输出上限、允许的数据范围、价格和密钥引用。原生结构化输出在验证通过的模型上启用；其他模型可返回 JSON 文本，后端执行相同校验。协议兼容、输出质量、实际计量分别验证。若网关在数据留存、资源或计量上不满足要求，同一 Worker 接口可直连经验证的兼容端点。

**配置与运维。** 运维管理平台采购的服务端 API 凭证；部署配置引用只读秘密文件或受限配置卷，普通用户无法指定 endpoint、路由和模型。网关端口仅内部可达，管理入口仅运维可达，网关调用使用专用密钥。接入前检查请求正文、调试追踪、遥测、插件和配置备份的实际默认行为，并用合成文本检查日志和持久化文件。只允许已批准目的地处理收藏。平台记录任务 ID、路由、用量、延迟和错误类别，以便计费核对和排障。

**故障与计费。** 由 Worker 统一负责尝试次数、预算预留和备用路由选择，验证网关不会在背后叠加重试或切换到未批准厂商。平台预算与用户额度按下文的预留机制执行；每一次收费尝试单独记账。发送后超时或缺少用量时标记待对账，避免把未知成本当成零。凭证无效时停用该路由并通知运维。模型不可用时收藏仍可打开和编辑。停止新模型调用即可回退，保留已有原文、人工关联和可追溯的建议。

**验证和发布。** 先在 OrbStack 使用合成收藏和两个不同厂商的正式 API 凭证，测试中文长短文本、空候选、无依据项目、无效 JSON、限流、超时及用量缺失。比较同一组输入的建议正确性、单条费用、端到端时延，以及网关和 Worker 在 4 核 4 GB 目标环境中的资源占用。再接入保存、排队、结果展示与人工确认，验证并发改文、删除、关闭处理和跨账号隔离。按内部账号逐步开放，观察建议接受与撤销情况；自动关联沿用下文的独立评测要求。真实网关与浏览器的实测范围见[开发计划](../ROADMAP.md)；双厂商实测与目标服务器容量验证仍待完成。

### 首批实现约定

- **配置与未启用行为。** 平台在部署侧启用文本整理。Worker 读只读路由配置（建议 `SPARK_AI_CONFIG_FILE`），其中包括网关地址、主备模型、密钥文件引用、输入输出上限和价格；启动时校验必需项。API 不需要模型密钥。平台未配置时继续正常保存并返回现有 `skipped / integration_not_configured`。配置齐全时仍须满足当前账号同意、单条未排除、材料可用。启用偏好不会触发历史全量重跑。
- **契约与界面。** 收件箱录入区提供 AI 入口，启用前说明用途与发送范围，`PATCH /me/preferences` 记录同意版本；`PUT /collections/{id}/ai-exclusion` 控制单条授权。详情以 `GET /collections/{id}/organization` 展示进度、标题与摘要，通过已有项目决定接口确认或拒绝。登录后的页面共享一条同源 SSE 连接，服务端只向会话所属账号推送状态变化。收到相关事件后按需读取最新状态；页面不定时查询。断线恢复后重新读取待确认建议，用户关闭提示或离开页面后仍能找回。确认与忽略以服务端保存的项目决定为准。用户主动重试使用同一路径 POST 和契约幂等约束；失败不清空原文。
- **数据与恢复。** 保留初始迁移，增量建立整理运行、预算预留/结算及 River 所需表。运行按账号与收藏归属查询；即使任务被重复领取，也只能应用一次。Worker 退出时停止领取；重启后恢复可执行任务。预算单位与日期按 [API 设计](API.md)；当前尝试可能已发送时保留预留、记录 uncertain，不能当作免费失败立即切换。确认未发送或可安全重试时，备用路由与重试共享同一总次数。
- **交付分工。** 后端负责迁移、Go API、Worker、契约必要修订及数据库集成测试。前端负责偏好与详情交互、项目建议和相关行为测试，并从共享契约生成前端类型。部署负责本地 Compose、镜像构建入口、内网网关与运维说明；Worker 命令约定为 `server/cmd/worker`，镜像内为 `/spark-worker`。总控协调契约变化并联调验收。生产启用与开发实现分开进行。
- **联调顺序。** 先验证关闭平台 AI 的既有保存流程，再通过隔离 PostgreSQL 和受控模型响应走通同意、创建、后台生成、展示和确认；覆盖跨用户项目、虚假引文、并发人工修改、额度竞争及网关中断。最后在可用的服务端凭证下，以相同合成输入验证实际主备厂商、费用和隐私配置。记录环境与实际结果；模拟适配器只用于验证应用行为。

## 输入和输出

一次运行固定 collection_id、user_id、content_version、user_policy_version、collection_policy_version、prompt_version、matching_policy_version。两种 policy_version 分别取用户与收藏的 ai_policy_version。提取器版本和项目候选快照随运行记录。

输入包括原始纯文本、用途说明、主要网址、已确认图片的 OCR、可读取的网页正文、用户已有标签及活动项目描述。总输入按模型上下文预算裁剪，保留每段的 source_id、内容版本和截取范围。

结构化输出见 [结果 Schema](../../contracts/organization-result.schema.json) 和 [合成样例](../../contracts/examples/organization-result.json)，包含 title、可选 summary、tag_candidates、project_candidates。项目候选包含 project_id、reason、evidence 数组和辅助 confidence。evidence 引用输入 source_id 与原文短片段。后端校验项目集合、字符长度、引用片段和输出 Schema，无法校验的候选不自动采纳。标签包含已有 tag_id 时校验名称和归属，新标签按用户命名规则匹配或创建。

建议标题最多 80 字、摘要最多 180 字、标签候选最多 5 个、项目候选最多 5 个，均作为初始策略参数。原文很短时 summary 可以省略。用户手动标题、标签与项目决定优先。

## 阶段与状态

| 阶段 | 执行内容 | 成功条件 | 失败后的可用材料 |
| --- | --- | --- | --- |
| extract_url | 公网网页标题和正文提取 | 获得有用标题或正文，记录是否截断 | 原始网址、用户原文和用途 |
| extract_images | 逐图 OCR，按需要生成视觉描述 | 每图记录独立结果，整体可部分成功 | 原图、已成功识别的其他图片 |
| generate | 生成标题、摘要和主题候选 | 输出格式、来源与长度校验通过 | 提取结果与本地规则结果 |
| match_projects | 匹配当前用户项目 | 候选 ID、项目版本和理由校验通过 | 已有人工关联与建议 |
| apply | 原子应用结果、更新关联及变更 | 输入、偏好、人工决定与生命周期检查通过 | 原有可用数据 |

阶段状态为 queued、running、succeeded、partial、failed、skipped、blocked。运行另有 superseded 表示输入或策略已过期。

queued → running；running → succeeded、partial、failed、blocked 或 superseded。用户关闭 AI、排除收藏、停用账号时未执行运行变为 skipped，执行中运行写回前转 skipped 或 superseded。资料被永久删除后运行载荷随清理删除。

必要阶段全成功为 succeeded，已有有用结果且某阶段终止失败为 partial，没有有用提取或生成结果且处理失败为 failed。没有适用输入的阶段为 skipped，不计入失败；额度导致无法继续为 blocked，并注明下一次可尝试时间。无项目候选属于正常整理结果。

## 网页与图片提取

网页抓取使用独立受限 HTTP 客户端，沿用现有公网地址、凭据 URL、重定向和超时防护。新正文提取增加内容类型、解压后大小、字符编码、正文清洗和长度控制。初始总超时 8 秒、重定向最多 3 次、解压后最多 2 MiB，保留可配置能力。登录页面或验证码页面记录提取受限，提示用户补充文字或截图。

原始网址保持用户提交值，抓取地址在单独字段规范化。每次重定向重新校验，固定本次解析得到的公网 IP；网络出口限制云实例元数据、内部域名和服务网段。测试覆盖 IPv4、IPv6、混合解析、DNS 变更和压缩大响应。

网页信息提取由独立 URL Worker 执行，并通过部署开关授权。当前只把所保存的主要网址用作请求目标，结果以纯文本存入当前版本的提取记录并参与搜索。人工标题、原文、用途和分类决定保留。网页提取目前独立于文字 AI 和 OCR，状态及手动刷新见 [API 设计](API.md#网页信息提取)。

图片从已确认 OSS 对象读取。OCR 字词作为 extracted_text，视觉描述记录为 inference，区别于原图可直接确认的文字。图像处理设置并发、像素、格式和响应大小上限。对纯风景或图标图片允许识别文字为空，后续依赖用途说明或视觉描述。

## 项目匹配策略

1. 读取用户活动项目及其版本，用户明确指定项目作为已确认关联。
2. 项目较少时完整提供名称、描述、关注点；较多时先按主题和历史确认资料选候选，记录被裁剪情况。
3. 模型基于实际材料提出候选和理由。用途说明权重优先，名称相似只提供候选线索。
4. 校验 ID 属于候选集合、证据引用有效、项目版本仍匹配。
5. 根据验证集校准的规则决定 auto 或 suggested；用户 rejected 的项目保持排除，manual/confirmed 保持有效。
6. 更新该运行负责的自动关联，清理旧版本已不成立的 auto/suggested 关联，保留人工决定和对应历史审计。

同一资料可以自动关联多个项目，所有项目都应有材料依据。模型自报 confidence 与规则证据、验证集表现一起决定采纳。新配置尚未验证时仅产生建议，内测发布需要完成自动关联的实际评测。

项目描述变化使对应候选失效，写回时跳过失效候选并按最新项目版本补充匹配。用户主动重新匹配历史资料时先展示范围与预计用量，再分批提交任务。首发可由当前收藏的重新整理入口逐条执行。

## 人工决定和竞争处理

| 竞争场景 | 处理结果 |
| --- | --- |
| AI 整理期间用户修改正文 | 旧运行 superseded，按新 content_version 入队 |
| AI 整理期间用户移除项目 | 写回读取最新 rejected 决定，保留移除结果 |
| 用户只修改标签或项目 | content_version 保持，decision_version 增加，AI 合并时保护这些决定 |
| 项目被暂停或完成 | 新自动匹配排除，已有有效关联继续展示 |
| 旧运行被重复执行 | 运行唯一性与应用标记防止重复写入 |
| 账号关闭 AI 后模型返回 | 记录可核算用量，停止应用该结果 |
| 用户删除收藏后模型返回 | 停止结果应用并交由清理生命周期处理 |

收藏写入、变更事件和任务同事务提交。Worker 不在数据库事务中等待网络。应用阶段按 DATA 的锁顺序执行，以收藏当前状态作为最终依据。

## 重试、额度和时延

网络暂时失败、429 和供应商 5xx 可退避重试，建议最多 3 次并加随机抖动；授权错误、无效输入和受限网页标为需修正或材料不足。重试预算按调用尝试预留，供应商支持幂等时传入稳定调用键。

首次调用前同时预留平台与用户当日预算，统一先锁平台预算、再锁用户预算。成功后按实际输入输出用量结算，确定未发送的失败释放预留，发送后状态不明的调用进入 uncertain。请求排队与重试设总期限，避免长期占用预算。

同一收藏内容与策略版本只安排一个活动运行。用户重新整理时复用可复用的提取结果，模型配置或提示版本变化时创建新运行。提示和模型响应只在受权限控制的业务存储中按必要保留期记录，普通日志保留 ID、错误码和用量。

初期后台并发建议为 2，网页和图片处理可分别设更低上限。界面分别显示“已保存”和当前整理阶段，支持离开页面后继续处理。

## 评测与发布记录

按 ROADMAP 建立至少 40 条人工标注材料，划分开发集与保留验证集。记录提取成功率、关键词可找回率、摘要事实错误、自动关联精确率与覆盖率、每条成本和 p50/p95 完成时长。

自动关联精确率目标至少 90%，必须同时给出样本数、自动关联数量、覆盖率及误关联样例。将错误归因到提取、候选召回、判断或写回，避免仅靠调提示修补数据问题。

模型、OCR、提示和采纳策略按版本发布。升级前用同一保留集合比较，回退时改变新任务配置，已保存结果保留来源版本。上线记录包含服务部署范围、调用格式、价格版本和用量上限。
