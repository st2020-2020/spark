# Spark 在线版产品需求

更新于 2026-11-18。本文定义产品定位与首个在线邀请内测版的目标产品行为，实施顺序与当前验证状态见 [开发计划](ROADMAP.md)，技术设计见 [系统架构](ARCHITECTURE.md)，首批之后的候选需求见 [产品迭代规划](ITERATION.md)。当前保留 MyGo 桌面版，并已实现在 OrbStack 运行的在线版首个纵向批次；本文全部功能尚未完成。

## 产品定位

**一句话定位。** Spark 是个人的灵感与资料收集本：把一闪而过的文字、网址和图片先收下，再归到正在做的项目里，需要时快速找回。

| 维度 | 内容 |
| --- | --- |
| 目标用户 | 在网上大量阅读、同时推进若干个人项目的人，例如开发者、设计师、研究者、内容创作者与自学者 |
| 核心场景 | 看到有用的东西却没空细看；过几天做项目时想不起放在哪；同一份资料对多个项目都有用 |
| 核心价值 | 收集零阻力、归类有依据、找回有路径 |
| 产品主线 | 收集 → 归类到项目 → 找回；新能力优先加强这条主线 |
| 区别所在 | 以「项目」组织资料，而非只按时间或标签堆叠；自动整理给出带原文依据的项目建议，由用户确认，人工决定始终优先 |
| 体验概念 | 「灵光手帐」：点阵手帐纸、按天排列的日志、纸条式卡片、项目纸胶带色、收集灵光的小瓶子标志；视觉规范见 [Web 视觉与交互规范](../apps/web/DESIGN.md) |
| 当前不做 | 团队协作与共享空间、公开社区与内容推荐、长文写作与文档排版、网页全文存档；如需调整，先更新本文 |

## 产品目标与已确定方向

用户上网时发现有用的信息，却没有时间立即阅读。Spark 接收文字、网址和图片，先保存，再自动识别、整理和关联正在进行的项目，帮助用户日后快速找回。

| 已确定事项 | 产品约束 |
| --- | --- |
| 面向个人 | 每个人拥有独立的收藏、项目、标签和附件 |
| 注册方式 | 自注册加邀请码，管理员批量导入并自行分发邀请码 |
| 首发终端 | 电脑和手机 Web，随后接入 MyGo 桌面同步及移动 App |
| 记录体验 | 快速输入、轻量格式、手帐式日志与卡片浏览；任意页面可随手记一条 |
| 内容输入 | 文字、HTTP(S) 网址、图片，可附用途说明 |
| 自动整理 | 自动识别内容、归类并关联用户创建的项目 |
| 云资源 | 腾讯云 4 核 4GB 承载早期应用，阿里云 OSS 保存附件 |
| 地域 | 按国内服务器、国内用户实施；具体云地域和系统待提供 |

## 建议默认值

下列是本轮制定的可调整产品默认值，实施时通过配置或明确的内容协议维护。

| 项目 | 默认方案 | 验证时机 |
| --- | --- | --- |
| 账号标识 | 邮箱和密码，验证邮箱后完成注册 | 账号模块实施前确认邮件服务 |
| 邀请码 | 一码一人，支持批次、到期和禁用 | 注册验收 |
| 输入格式 | 段落、加粗、高亮、有序及无序列表、链接 | Web 和 MyGo 内容往返验证 |
| 输入上限 | 正文与用途说明合计 50,000 字；每条最多 9 张图片，每张 5 MiB | 内测上传与资源压测 |
| 图片格式 | JPEG、PNG、GIF、WebP | 上传校验 |
| 回收站 | 保留 30 天，用户可提前永久删除 | 恢复与清理验收 |
| 阅读标记 | 打开详情后标记已读，允许重新标为未读 | 手机和电脑交互验收 |
| AI 开启 | 用户完成首次数据处理说明后，启用后续收藏自动整理；可全局关闭或排除单条 | 内测首次使用流程 |
| 自动项目关联 | 根据内容、用途说明与项目关注点判断，支持多个项目 | 使用标注材料校准自动关联条件 |
| AI 额度 | 管理后台配置每日预算、每用户额度和任务并发 | 用实测成本确定数值 |

## 首发闭环

1. 管理员导入邀请码。用户验证邮箱并兑换邀请码，进入自己的空间。
2. 用户可以先创建项目，填写名称、简短描述和关注点，也可以直接收藏。
3. 粘贴文字或网址、上传截图，可补一句用途，并可手动指定项目。
4. 原始内容保存后立即显示卡片和“已保存”。后台逐步补充提取内容、标题、摘要、标签与关联项目。
5. 用户按项目、时间、阅读状态和内容类型浏览，或者搜索标题、原文、成功提取的正文、OCR 文字和标签。
6. 用户打开原文或原图、修改归类、补充用途，之后仍可通过项目与搜索找回。

首发交付账号、项目、收藏、自动整理、关键词找回、回收站和必要管理后台。后续阶段加入浏览器扩展、语义检索、桌面离线同步、移动 App、项目资料汇总和问答。

## 页面与操作

| 页面 | 主要内容与操作 |
| --- | --- |
| 收件箱 | 顶部收集框，按天分组、倒序排列的收藏日志，整理进度，未读筛选 |
| 随手记 | 在任意非收件箱页面弹出的快速收集面板，与收件箱收集框共用草稿 |
| 项目列表 | 进行中、暂停、已结束项目，名称、描述、关注点和收藏数 |
| 项目详情 | 项目介绍、关联收藏、搜索、类型和阅读状态筛选 |
| 全部收藏 | 分页浏览及组合筛选，搜索结果突出命中片段 |
| 待归类 | 尚未确定项目关联的收藏，显示候选项目与简短依据 |
| 收藏详情 | 原始内容、来源、用途说明、附件、提取内容、整理结果和关联原因 |
| 回收站 | 恢复、永久删除、剩余保留时间 |
| 账号设置 | 账号、界面外观（四套主题配色与明暗模式）、会话、AI 偏好和用量 |
| 管理后台 | 邀请码导入与禁用、用户状态、处理失败统计、模型配置和预算 |

手机端底部或顶部保留明确的收集入口。上传中、保存中、离线草稿、整理失败和无搜索结果均提供下一步操作。管理员查看运行信息时采用元数据和脱敏错误信息。

## 三个贯穿开发的验收场景

### 链接用于开发 Spark

用户创建“Spark 产品开发”，关注多端同步、快速收集和搜索。保存一篇同步文章，并备注“离线冲突处理可以参考”。保存后可在收件箱立即找到链接，整理后标题、摘要和主题合理，关联到该项目并解释依据。搜索“同步”或原文中的词能够找回并打开来源。

### 截图用于参考交互

用户上传搜索界面截图，并备注“参考这个筛选交互”。原图可预览，成功识别的截图文字可搜索，项目关联同时考虑图片文字和用途。文字识别失败时仍能打开原图，并可补充说明或重试。

### 一份资料服务于多个目的

用户有“Spark 产品开发”和“数据库学习”两个项目。一篇数据库文章可以同时关联两者。用户移除其中一个自动关联后，该决定在后续重新整理中继续生效。暂停或结束项目后，既有资料仍可浏览，新的自动关联只考虑进行中的项目。

## 自动整理规则

| 环节 | 行为与失败处理 |
| --- | --- |
| 保存 | 输入和归属校验后持久化；网络重试返回同一收藏；草稿在成功确认后清空 |
| 图片上传 | 每张图片显示进度；失败可重试或移除；完成全部所选附件确认后创建正式收藏 |
| 网页提取 | 获取可读取的标题和正文，保留来源与提取时间；受限网页记录失败原因，提供补截图或粘文字入口 |
| 图片识别 | 提取 OCR 文字，视觉描述作为单独推断结果；可识别范围不足时显示说明 |
| 标题和摘要 | 从实际取得的材料生成；手动标题拥有优先级；纯链接提取失败时展示域名等可验证信息 |
| 标签 | 优先使用用户已有主题标签，用户增删决定参与后续处理 |
| 项目关联 | 输出项目 ID、关联理由和依据片段；用户指定项目优先；依据不足时展示建议或进入待归类 |
| 重复内容 | 首期允许重复保存；每次请求重试保持幂等；后续提供同网址或相似内容提示 |
| 重新整理 | 根据最新内容执行，保留用户确认和排除结果；项目描述变化后可主动重新匹配历史收藏 |
| 暂停 AI | 收藏、手动归类和关键词搜索继续可用；待执行任务取消或跳过，已发出的调用可能完成，关闭后的结果停止应用 |

短内容允许只有标题和标签，摘要按内容长度决定。AI 内容保留生成来源与材料版本。项目关联的自动采纳条件通过标注集验证，模型自行给出的分数只作为辅助信号。

## 状态与数据生命周期

保存状态、整理状态、项目归类状态和阅读状态分别表达。一条收藏可以“已保存、部分整理、已关联、未读”。无适合项目且处理成功时，显示“待归类”。

用户删除收藏后进入回收站，正常列表、搜索和新整理任务均排除该内容。恢复时重新检查提取和归类是否需要补齐。到期或永久删除后清理正文、附件、提取结果及后续建立的检索索引，必要删除标记按同步协议保留。备份有独立保留期，恢复备份后重放删除清单。

## 内测验收

| 检查 | 通过条件 |
| --- | --- |
| 保存可靠性 | 超时重试、重复点击和 Worker 重启后，原文与附件完整，幂等请求只创建一条 |
| 用户隔离 | 两个用户互换收藏、附件、项目和搜索请求中的 ID，无法读取或修改对方内容 |
| 自动关联 | 标注集覆盖明确关联、多项目、无匹配、短文本、识别失败和用户纠正；自动关联精确率目标至少 90%，同时报告覆盖率和样本数 |
| 找回 | 固定测试集中，标题、原文及成功提取的 OCR 关键词均能找回目标；5 名内测用户尝试查找各自历史收藏，记录成功率和用时 |
| 性能 | 按开发计划的测试负载测量保存与搜索；AI 时延单独统计 |
| 恢复 | 从独立备份恢复到干净环境，核对收藏、附件关联、账号和删除状态 |

上述数值是验收目标，实际测量结果进入每阶段交付记录。
