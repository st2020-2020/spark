# Spark Web 设计上下文

2026-11-16 更新：用户要求参考 flomo，重做在线版的交互与样式。本文件是本轮 Web 视觉实现依据；本轮双态编辑器、底部图标工具栏、格式浮层与顶部搜索已实现，并在 OrbStack 容器及真实浏览器中验证。根 [DESIGN.md](../../DESIGN.md) 与 [UX-CONTRACT.md](../../UX-CONTRACT.md) 仍仅描述 MyGo。业务交互以 [WEB.md](../../docs/design/WEB.md) 为准，字段以契约为准。

## 方向与依据

收集先于整理，原文先于元数据。参考 [flomo 官方快速记录说明](https://help.flomoapp.com/basic/quick-input.html) 的轻量输入、连续阅读和低干扰工具；不复制品牌、资源或未核实的登录后界面。[交互稿](../../docs/design/spark-web-preview.html) 展示收件箱、项目、搜索、详情及手机布局，内容为独立示例，不连接账号、不持久保存。

现有实现的问题：编辑器像业务表单，格式与附件工具始终抢占注意力；侧栏重复提供收集按钮；卡片标题、正文、状态和项目缺乏主次；工程连接信息进入日常界面。重构应让用户进入页面就能写，保存后能连续读，想整理时再选择项目。

采用 design-taste-frontend 的克制配色、排版、真实内容与控件一致性原则。此处是长期使用的应用，不采用该技能面向营销页的整屏分段、随机 hero、WebGL、展示动画或额外门禁脚本。依照 AGENTS.md 复用现有验证，不建立证明文件和审计流水。

## flomo 登录态实测补充（2026-11-16）

用户指定 ego-browser，已在其登录态访问 [flomo 全部笔记](https://v.flomoapp.com/mine?)，实际观察初始、hover、聚焦、临时输入、格式浮层、搜索与筛选、导航和卡片菜单。以下为当前账号、1920×940 CSS 视口的观察，不是 flomo 的跨设备通用规格。没有提交笔记、触发 AI 或修改账号配置；临时输入已清空，刷新确认编辑器为空。未保存账号名、笔记原文或页面资产到仓库。

| 顶部搜索 | 初始约 240×36px 浅灰圆角输入，左搜索图标、快捷键占位，右筛选；聚焦展开到 400px，白底边框，下方展示搜索面板与模式 | 桌面页标题右侧提供真实搜索输入，可在剩余空间内扩展，Cmd/Ctrl+K 聚焦，Escape 返回；跳转/同步沿用 /collections 的字面搜索，不接入假的 AI 搜索。移动端保持独立搜索页 |

这次实测纠正了前两轮只缩减高度、保留文字按钮与顶部格式栏的处理。以下章节已同步替换为本轮实际实施的规范，不再叠加旧版尺寸与文字工具条规则。

## 页面骨架

| 视口 | 结构与尺寸 |
| --- | --- |
| >= 1024px | 工作区内容 944px 居中（含左右 32px 留白最大容器 1008px）；侧栏 224px、间距 40px、主列最大 680px；宽度不足时先收缩主列；顶部留白 40px |
| 768–1023px | 56px 顶栏 + 可关闭导航抽屉，单列最大 680px（含左右 24px 最大 728px）；不额外加底部导航 |
| < 768px | 52px 顶栏、左右 16px、单列；底部 56px 导航加 safe-area；输入时保证编辑器与保存操作不被键盘遮挡 |

桌面侧栏与页面共用灰白背景，不再成为全高白色管理菜单。品牌为文字 Spark，保留简单原有标记即可，不新造 logo。导航为「收件箱」「全部收藏」「待归类」，下方独立「项目」分组，最多展示 5 个真实进行中项目与「查看全部」；仅在成功加载且全库没有任何项目（含暂停与已结束）时，显示「创建项目」入口打开现有新建流程并隐藏无意义的「查看全部」；若仅无进行中项目但存在暂停/已结束项目，仍保留「查看全部」；加载或失败时不冒充空项目。不可用本页条数冒充全库计数。底部为回收站、账号菜单；设置、退出、管理员入口收进账号菜单，管理权限仍由服务端验证。当前导航采用 `--sp-primary` 绿色实底与 `--sp-on-primary` 高对比文字，未选中项 hover 为中性浅底；侧栏及常用导航图标统一视觉重量（`strokeWidth=2`）。

日常列表页（收件箱、全部收藏、待归类、项目、项目详情、回收站）复用统一页头组件：标题在左，桌面右侧同行提供 `240px` 浅灰圆角搜索框，聚焦可平滑扩至最多 `360px`（不挤压标题或溢出），支持全局 `Cmd/Ctrl+K` 聚焦与 `Escape` 恢复触发前焦点；IME 组合输入中回车不跳转，提交跳转至 `/collections?q=...`；移动端保留独立搜索页 `/collections`。所有主列页标题、收集框、筛选条、卡片边缘对齐。页面标题 22px，无大幅口号；管理员表格页允许主列扩至 980px，仍复用侧栏和控件。断点统一在样式入口，禁止组件各用一套 900/1024 切换规则。

## 首屏与组件

### 收集框：静息轻量，聚焦展开

无必填标题，默认不展开 URL、用途、项目、多行属性表单。收集框设静息与激活双态（16px 内边距、12px 圆角）：
- **静息态**：正文一行最小高 30px，底部工具栏高 36px，整体约 110px，极轻边框阴影；提示「记下想法，或粘贴网址…」。
- **激活态**：明确点击/聚焦编辑器或交互工具后平滑（约 220ms）展开至正文最小 92px、整体约 170px，显示主题绿色边框与明显阴影；不复制 hover 抢焦点。一次激活后失焦不立即缩回；存在本地草稿或保存失败持续保持激活；保存成功且焦点移开收集框后回到静息。

移除顶部常驻/展开富文本工具条，改为编辑器底部纯图标短竖线分组工具栏（收集框与详情页正文编辑器复用同一套底部工具栏）：
- **左侧三组**：`添加项目`（文件夹图标，搜索选择项目）、`附加链接`（插入/编辑正文链接浮层）| `Aa`（点击在按钮上方打开小型浮层，仅含契约允许的 `加粗` / `高亮`）、`无序列表`、`有序列表` | `更多`（包含 `撤销`、`重做`，收集框另包含 `补一句用途`、`附加网址`、`可选标题`）。点击工具或开关浮层不引起正文跳动，保留鼠标/选区高亮（`onMouseDown` 阻止抢焦点）；所有浮层支持 `Escape` 关闭并恢复触发焦点，移动端 `< 768px` 横跨工具栏宽度且较大浮层（添加项目/附加链接/更多）向工具栏下方展开，避免撞到顶栏或溢出裁切。
- **右侧保存区**：有输入时显示清晰可读的字数计数（近上限提示阈值）；独立发送图标按钮（`aria-label="保存收藏"`，tooltip 含 `⌘/Ctrl+Enter`），空白禁用、合法启用主绿、保存中明确 loading 旋转指示、失败保留内容与本地草稿并支持同幂等键重试。

本批只支持文字/网址；不在空态提示粘贴图片，不展示可点击但必然失败的上传/标签/@AI 按钮。未来能力按 WEB.md 接入，不能为了这次外观重构删掉已存在的附件阅读保护。草稿、幂等、会话与失败处理均不改。

收件箱无筛选初始空态不套白卡、边框或大标题，列表区域使用左对齐简短提示「保存的内容会出现在这里。」，辅以 13px「先记下来，项目可以稍后再选。」；筛选无结果仍保留可清除筛选，加载失败仍单独报错。

### 卡片：正文是第一层

顺序为「时间与未读点 → 正文 → 来源链接（存在时）→ 项目关联」。时间一行低强调；未读点附可读名称。仅在有用户自定义标题时展示标题，不能把正文首句同时显示成标题和摘要。若 DTO 不能可靠区分自动标题，文字卡优先省略标题，不猜测或修改契约。卡片 hover 仅增加极轻阴影，无抬升位移或重排。

正文 16px，最多约 8 行并提供明确「查看全文」；不得改变真实段落或富文本语义。网址显示域名和可用标题，不凭空制造站点摘要/缩略图；已有关联项目用小文件夹图标与绿色文字，不堆满色块。没有项目就留白，无需每张卡重复「未分类」。类型不反复贴「文字」标签。

正文可选中复制；使用语义明确的详情链接，不把含按钮/外链的整张卡嵌入一个 Link。更多按钮桌面 hover/focus 时强调，手机 44px 始终可见；菜单分组排列（阅读状态/编辑 → 分隔线 → 底部危险操作「移入回收站」），支持 `Escape` 关闭并返回焦点，不新增未接入的分享或 AI 按钮。加载、失败、离线与重试仍可见；`integration_not_configured` 不作为每张卡的失败警报，详情集中说明「自动整理暂未开放」。

### 筛选与搜索

收件箱下方只有「全部 / 未读」与轻量筛选入口；类型等次级条件按需展开，去掉常驻刷新按钮（错误状态保留重试）。全部收藏页顶部直接是搜索输入；按现有防抖、取消和 URL 同步工作。选中的条件必须可见且可逐项清除。搜索模式有「结果」反馈，无结果与请求失败明确区分；不得把现有局部分页结果作为总数。

### 项目与详情

项目列表使用名称、简短描述、状态组成的安静行列表，避免仪表盘统计卡；只有后端可靠返回时显示资料数。项目详情是标题/可展开描述、当前项目收集框和资料流，不再横向堆属性卡。

收藏详情延续同一阅读宽度，顶部「返回」恢复来源列表位置。正文与来源先显示，随后用途、项目关联；历史修订与技术状态折叠至次级区域。编辑为显式动作，取消不改变远端数据。人工 include/exclude/reset 和 409 冲突比较保留，禁止将版本冲突简化成覆盖确认。

### 手机和其他页面

手机底栏「收件箱 / 项目 / 搜索 / 更多」；更多打开同一导航抽屉。顶栏右侧用安静的「记一条」入口定位收件箱编辑器并聚焦，复用现有草稿，不同时生成另一个独立编辑器。收件箱首屏已有编辑器时不重复显示该入口。输入聚焦时隐藏底栏，保存按钮随编辑区可达；测试软键盘和安全区，不只检查宽度。

登录/注册/重置使用 400px 最大宽度的简洁表单，保留可见 label、44px 输入和清晰错误；移除日常健康检查成功文案。服务不可用用「暂时无法连接，请重试」等可理解提示；诊断地址仅在显式开发诊断区域。测试适配器的模拟标识必须保留，不能混淆为真实数据。

设置与管理员页面沿用同一控件和间距。保留可用能力；未实现的预算/模型等分组显示一次「暂未开放」并禁用操作，不渲染假数据或一屏重复 404。回收站保留恢复与撤销，永久删除未接入前不能提供假成功按钮。

## 前端实施边界与顺序

1. 先合并本会话已有依赖修复，保护锁文件；在 `tokens.css`、`global.css`、`AppShell.tsx` 建立统一骨架。删除被替代样式，不并存两套皮肤。
2. 改造 `CollectionComposer`、`RichTextEditor`、`CollectionCard`，先完成收件箱。共享组件负责共同样式/行为，页面不复制变体。完成后回报真实截图，可继续开发无需等待新审批。
3. 同步项目/搜索/待归类/详情/回收站；最后统一账号、设置与管理页。路由、API 类型、认证、草稿隔离、版本轴、幂等与安全渲染保持有效。
4. 只修改 `apps/web/`，共享契约、后端、部署和根文档冲突交主会话处理。本文件为视觉依据，`WEB.md` 为行为依据；交互稿为表现参考，不能将演示内存逻辑搬入产品。

所有本机运行与联调通过 OrbStack Compose；不启动宿主 Vite/API/PG。复用现有类型检查、构建、行为测试，在容器栈真实账号完成登录→建项→收集→编辑→归类→搜索→删除撤销；复测 IME、失败保留草稿、409、账号切换、键盘焦点。浏览器检查 1440/768/390、长中文/长链接、空态与错误态及明暗主题，不用 `overflow-x:hidden` 掩盖布局错误。仅对新增行为或回归风险补必要测试，不新增门禁脚本。最终报告区分原型审阅、模拟测试和真实 API 联调结果。
